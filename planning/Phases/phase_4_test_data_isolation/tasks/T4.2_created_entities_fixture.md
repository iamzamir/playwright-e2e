## 1. Problem
Cleanup today is per spec, hand-written, and often missing. When a test fails before its own cleanup step, the data stays. A shared fixture that records what was created and deletes it through the API at teardown gives every spec reliable cleanup with one line per created entity.

## 4. Implementation steps
1. **Types** in `util/created-entities.util.ts`:
   ```ts
   export type EntityKind = 'process' | 'scenario' | 'view' | 'viewGroup' | 'scopeFilter' | 'calendar' | 'supplyChainAction' | 'actionItem' | 'procedureMapping';
   export interface CreatedEntity { kind: EntityKind; id?: string; name: string; context?: Record<string, string>; createdBy: string; }
   export type Deleter = (entity: CreatedEntity) => Promise<void>;
   export class CreatedEntities {
     private readonly items: CreatedEntity[] = [];
     register(kind: EntityKind, name: string, extra: { id?: string; context?: Record<string, string> } = {}): void { /* push with createdBy = test title */ }
     list(): readonly CreatedEntity[] { return this.items; }
     async cleanup(deleters: Partial<Record<EntityKind, Deleter>>, log: (msg: string) => Promise<void>): Promise<{ deleted: number; failed: CreatedEntity[] }> { /* delete in reverse order; catch and log each failure; never throw */ }
   }
   ```
   - Reverse order matters: delete mappings before views, child scenarios before parents, subprocess before process.
   - A missing deleter for a kind is logged as a failure ("no deleter for <kind>"), never silently skipped.
2. **Deleters** in `util/entity-deleters.util.ts`. One function per kind, built on the helpers listed in section 2. Each must be idempotent: a 404 counts as success. Each gets its token once per cleanup run.
3. **Fixture scope.** Add `createdEntities` as a **worker-scoped** fixture in both `configs/fixtures.ts` and `configs/api-fixtures.ts`:
   ```ts
   createdEntities: [async ({}, use, workerInfo) => {
     const registry = new CreatedEntities();
     await use(registry);
     const result = await registry.cleanup(defaultDeleters(), msg => logger.info(msg));
     // write reports/cleanup/<workerIndex>.json for the triage pack; never throw
   }, { scope: 'worker' }],
   ```
   - Worker scope runs teardown after the worker's last test, even after failures, and fits `describe.serial` specs that share data across test cases.
   - For specs that need cleanup after each file (to keep the environment small during long runs), also expose `test.afterAll(() => createdEntities.cleanupFile(...))`. Keep it optional.
4. **Reporting.** Attach `cleanup-summary.json` (deleted and failed lists, names only, no tokens) to the last test of the worker, or write `reports/cleanup/*.json` and let `scripts/triage/enrich-allure-results.js` pick it up. Choose the simpler option and record it.
5. **Unit tests** `tests/_framework/created-entities.spec.ts` with stub deleters: reverse order; failure in one deleter doesn't stop the others; missing deleter reported; 404 is success.
6. **Docs.** `playwright-specs.instructions.md`: "Register every entity a spec creates: `createdEntities.register('scenario', name)` right after creation succeeds."
