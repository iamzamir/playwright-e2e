## 1. Problem
Specs make "unique" names with a random three-digit suffix (900 possible values). Parallel workers and shards can pick the same name, and a leftover from a failed run can clash with a new one. The names also don't say which run created them, so bulk cleanup can't target them safely.

## 2. Evidence (verified 2026-10-08 on `main` @ `f3d48bb`)
- 32 spec files use `Math.random`. By folder: PS ScenarioBatch 6, ScopeBatch 5, SupplyChainActionsBatch 4, DrillThroughBatch 2, CardsBatch/LiveBlocks/NPI 1 each; PO UI ProcessBatch 3, ScopeBatch 2, ViewManagerBatch 1; backend Migration 3, ProcessBatch/LinkManagement/Calendar 1 each.
- `GITHUB_RUN_ID` and `GITHUB_RUN_ATTEMPT` are available in CI; locally, neither is set.

## 4. Implementation steps
1. Create `playwright-e2e/util/unique-name.util.ts`:
   ```ts
   import { test } from '@playwright/test';

   const AUTOMATION_TAG = 'pwauto';

   const STAMP_WIDTH = 8;   // Date.now() in base36 is 8 characters until the year 2059
   const SEQ_WIDTH = 2;     // up to 1,296 names per millisecond per worker
   let lastStamp = 0;
   let seq = 0;

   export function runId(): string {
     const ci = process.env.GITHUB_RUN_ID;
     if (ci) return `${ci}${process.env.GITHUB_RUN_ATTEMPT ? `a${process.env.GITHUB_RUN_ATTEMPT}` : ''}`;
     return process.env.PW_LOCAL_RUN_ID || 'local';   // set once in playwright.config.ts, see below
   }

   function slot(): string {
     try {
       const info = test.info();
       return `s${info.config.shard?.current ?? 0}w${info.workerIndex}`;
     } catch {
       return `s0w${process.pid}`;   // outside a test (global setup, scripts)
     }
   }

   function nextStampAndSeq(): string {
     let now = Date.now();
     if (now === lastStamp) {
       seq++;
       if (seq >= 36 ** SEQ_WIDTH) {
         while (Date.now() === now) { /* wait for the next millisecond */ }
         now = Date.now(); seq = 0;
       }
     } else {
       seq = 0;
     }
     lastStamp = now;
     return now.toString(36).padStart(STAMP_WIDTH, '0') + seq.toString(36).padStart(SEQ_WIDTH, '0');
   }

   export function uniqueName(prefix: string, maxLength = 60): string {
     const suffix = `_${AUTOMATION_TAG}_${runId()}_${slot()}_${nextStampAndSeq()}`;
     const room = maxLength - suffix.length;
     if (room < 1) {
       throw new Error(`uniqueName: maxLength ${maxLength} is too short; the suffix alone is ${suffix.length} characters (${suffix}).`);
     }
     return `${prefix.slice(0, room)}${suffix}`;   // only the prefix is ever shortened, so the suffix stays parseable
   }

   export const AUTOMATION_NAME_PATTERN = new RegExp(`_${AUTOMATION_TAG}_([a-z0-9]+)_s\\d+w\\d+_([a-z0-9]{${STAMP_WIDTH}})([a-z0-9]{${SEQ_WIDTH}})$`, 'i');

   export function parseUniqueName(name: string): { runId: string; createdAt: Date } | undefined {
     const m = AUTOMATION_NAME_PATTERN.exec(name);
     return m ? { runId: m[1], createdAt: new Date(parseInt(m[2], 36)) } : undefined;
   }
   ```
   Why each part is there:
   - **Shard and worker** (`s<shard>w<worker>`): shards on different runners share one `GITHUB_RUN_ID` and all start at worker 0, so the worker index alone isn't unique within a run.
   - **Sequence**: two calls in the same millisecond in one worker would otherwise produce the same name.
   - **Length check**: when `maxLength` can't fit the suffix plus at least one prefix character, it throws instead of returning a name longer than allowed. Call sites with short field limits must pass a short prefix or a larger limit the entity accepts.
   - **`parseUniqueName`**: T4.5 reads the creation time from the name when the API doesn't return `createdAt`.
   - **Local run id**: set it in the main process so every worker shares it. In `configs/playwright.config.ts` (it's loaded before workers start, and workers inherit `process.env`): `process.env.PW_LOCAL_RUN_ID ??= \`local${Date.now().toString(36)}\`;`. Setting it lazily inside `uniqueName` would give each worker process a different id. Verify with two workers that the names share the run id.
   - The base36 timestamp, sequence and run id are lowercase alphanumeric; check that every entity type accepts `_` (next bullet).
   - **Field limits:** check the maximum name length and allowed characters for each entity type you'll name (process, scenario, view, filter, calendar, SCA). Some UIs reject `_` or long names. Read the sibling repo DTO validation (`C:\Backend\<repo>`, per `.agents/learnings.md`) and set `maxLength` per call site, or add a per-entity wrapper.
2. Unit tests `tests/_framework/unique-name.spec.ts` (no browser): 10,000 calls in a tight loop in one worker are all distinct (this exercises the same-millisecond sequence); every name matches `AUTOMATION_NAME_PATTERN` and `parseUniqueName` returns a creation time within 1 s of now; `uniqueName(p, n)` never returns more than `n` characters; a `maxLength` shorter than the suffix throws; it works outside a test.
3. Replace in the 32 specs. Typical pattern:
   ```ts
   // before
   const scenarioName = 'AutoScenario' + (Math.floor(Math.random() * 900) + 100);
   // after
   const scenarioName = uniqueName('AutoScenario');   // default maxLength 60; pass the entity's real limit if it is lower
   ```
   - Keep prefixes unchanged. DataSetup cleanups and other specs may search by prefix (`grep -rn "<prefix>" tests` before changing anything). The suffix is about 38 characters in CI, so a limit below ~45 truncates the prefix; if an entity's limit forces that, record it and make sure no cleanup depends on that prefix.
   - If a test asserts on the exact format (for example, a list sorted by name), adjust the assertion to the new format.
4. Add a line to `.github/instructions/playwright-specs.instructions.md`: "Names for created data come from `uniqueName(prefix)`".
5. Lint (T2.2): add a warn-level `no-restricted-syntax` for `Math.random` in `tests/**`.
