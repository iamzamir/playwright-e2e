## 1. Problem
Nobody can say which specs are expected to run on QA or PSR. Test data exists for 213 specs on INTEROP, 120 on QA and 39 on PSR, but a missing QA file can mean "not meant for QA" or "forgotten". The generated catalog doesn't show tags or environments.

## 2. Evidence (verified 2026-10-08 on `main` @ `f3d48bb`)
- Specs with a matching `testdata/<ENV>/<path>.json`: INTEROP 213, QA 120, PSR 39 (of 237).
- QA runs nightly only for the PO backend (2 crons); INTEROP for all functional suites; PSR runs JMeter (`po-backend-performance-test-psr.yaml`, currently commented-out cron).
- `scripts/generate-testcase-docs.js` produces `docs/testcases/*.md` and `test-cases-index.csv` without tags.

Re-check:
```bash
cd playwright-e2e
for e in INTEROP QA PSR; do n=0; for s in $(find tests -name "*.spec.ts" | sed 's#^tests/##; s#\.spec\.ts$##'); do [ -f "testdata/$e/$s.json" ] && n=$((n+1)); done; echo "$e: $n"; done
```

## 3. Scope
- **In:** environment intent per area (a short policy); `@env-qa` / `@env-psr` tags on specs meant for those environments; the docs generator showing tags and environments; a validator check that a spec tagged for an environment has its test data there.
- **Out:** creating the missing test data (one follow-up task per area if the policy says the specs should run there).

## 4. Implementation steps
1. **Policy** (ask the user or the team; recommendation in brackets): PO backend → INTEROP and QA [all]; PO UI → INTEROP [QA later]; PS UI → INTEROP; DataSetup → INTEROP (+ QA for backend data); Performance → INTEROP and PSR. Write it into `playwright-e2e/docs/strategy/test-strategy.md` (an "Environments" section) and link it from the master plan.
2. **Tags:** add `@env-qa` / `@env-psr` (T6.2 vocabulary) per the policy, using a script similar to T6.2's.
3. **Validator** (T2.3): new check. A spec tagged `@env-<x>` must have `testdata/<X>/<path>.json` if it reads test data (detect by the `testData` fixture parameter or a `require('../../testdata/' + process.env.PSENV …)` pattern). Report ERROR.
4. **Docs generator:** add `Tags` and `Environments` columns to the per-area Markdown tables and the CSV; add a coverage summary to `TEST-CASES.md` (area × environment counts). Keep the output format otherwise unchanged (the drift check in T2.4 compares it).
5. Regenerate the docs; list the gaps (spec tagged for QA but missing QA data) as follow-up tasks.
