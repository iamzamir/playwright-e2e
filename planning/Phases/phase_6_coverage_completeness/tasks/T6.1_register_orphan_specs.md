## 4. Implementation steps
1. For each of the 13 PS specs, run it alone on INTEROP (`npm run test:target -- tests/PlanningSpace/<path>` from `playwright-e2e/`; on PowerShell call `npx playwright test` directly). Record pass or fail, runtime, and whether it creates data.
2. Decide per spec, with the user for anything other than "register":
   - Passes and is relevant → add to the matching suite JSON. Pick the suite whose globs already cover sibling specs (for example ObjectiveBar → `ObjectiveQuickLinksViewSearchBatch.json`). Check the suite's runtime stays under its shard budget (look at the matrix `workers` and recent run durations).
   - Fails because of the product → register it and add a known issue (Jira key), so it's tracked and not hidden.
   - Fails because of the test → register it, then a separate `bugfix/` task, or keep it on the allow-list with "broken, see T<id>".
   - Obsolete feature → delete with the user's OK, and regenerate the docs.
3. Add `"addlanepopup": "tests/PlanningSpace/AddLanePopup"` to the PS workflow `folder_map` (`.github/workflows/playwright-ps-iop-ui-local-suite.yaml`).
4. For the three `TEST_IGNORE` specs, find out why they were parked (`git log -S "<spec name>" -- playwright-e2e/package.json`), run them once, and either re-enable them or record the reason in `_unscheduled.json` with a Jira or task link.
5. PO UI (29), DataSetup (10), Performance (4): confirm the allow-list reasons ("runs by `test:interop:poui:<batch>`", "destructive, nightly DataSetup job or manual", "Sauce performance workflow"). No other change.
6. `npm run docs:testcases` if suites changed titles; `npm run validate:suites` passes with no `TODO T6.1` left.
