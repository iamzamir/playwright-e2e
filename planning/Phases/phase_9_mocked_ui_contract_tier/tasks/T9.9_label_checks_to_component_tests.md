## 1. Problem
About 26 PowerBar and ViewSearch tests check labels and search filtering. They are already fast, so mocking saves little time. Pure label checks belong in the MFE's component tests, which run on every dev PR and catch the change where it is made. This task lists which checks to hand over, agrees it with the MFE owners, and trims each spec to one real test per context once the component tests exist.

## 2. Evidence (verified 2026-10-27 on `main` @ `4d5cf28`)
- `tests/PlanningSpace/PowerBar` (001–005) and `tests/PlanningSpace/ViewSearch` (001–003).
- `plan-sop-planning-mfe` has 333 test files and already tests `ScopeChip`, `ScenarioChip`, `ContextOverrideChip` and `ScenarioFilter`. `plan-sop-lui` has 297.

## 3. Scope
- **In:**
  - A mapping table: each PowerBar and ViewSearch check → "component test exists" / "component test needed" / "stays E2E".
  - A handoff issue for the MFE owners.
  - After their PRs merge: trim the E2E specs to one test per context.
- **Out:** writing tests in the dev repos (owned by their teams).

## 4. Implementation steps
1. For each test, note what it asserts, and search the dev repos for an existing test of the same component (`Select-String` in `C:\Backend\plan-sop-planning-mfe\src`, per the learnings).
2. Write the mapping into `playwright-e2e/docs/analysis/powerbar-viewsearch-component-handoff.md`.
3. Open the handoff in the MFE team's tracker with the "component test needed" list (needs the user's OK before posting).
4. When their tests merge, trim the E2E specs and regenerate the docs.
