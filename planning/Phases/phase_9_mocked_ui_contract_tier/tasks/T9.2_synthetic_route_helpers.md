## 1. Problem
A HAR only holds what INTEROP returned on the day it was recorded. Some states can't be recorded on demand: a planning instance in the "Error" or "Started" state, an empty list, a 403 on a card endpoint, a 500, or a response slow enough to show the loader. The ODM status specs and the unified empty and error states fail every night because the cluster isn't in the state the test expects. These states need responses built in the test, starting from a real recorded shape so they don't invent fields.

## 3. Scope
- **In:**
  - `util/api-mock.util.ts`, with:
    - `mockJson(context, url, body, { status })`
    - `mockFromHar(context, harPath, url, transform)`: take the recorded entry and change the fields that set the state.
    - `mockStatus(context, url, status)` for 401, 403 and 500.
    - `mockDelay(context, url, ms)`: continue the request after a bounded `getTimeout` tier, never `waitForTimeout`.
  - A unit test for the HAR transform.
  - One "proof" spec per helper in `tests/PlanningSpace/Mocked/`.
- **Out:**
  - Migrating the ODM specs (T9.6) and the loader and empty-state specs (T9.8).
  - Mocking WebSockets (LiveBlocks): not planned.

## 4. Implementation steps
1. **Find the endpoints.** For each state in section 2, record the calls of one real run with `PW_NETWORK_BODY_FIDELITY=full PW_NETWORK_ARTIFACT_MODE=always`, and list the endpoint and the field that sets the state (for example `status: "ERROR"`) in this file's section 2.
2. **`util/api-mock.util.ts`.**
   - Every helper puts its route on `page.context()`, for the same reason as T9.1.
   - Each helper returns an `unroute` function and logs `[MOCK] <method> <pattern> → <status>` through `CommonFunctions.logMessage`, so the Allure report shows which responses were mocked.
   - `mockFromHar` reads the HAR with `fs` and finds the entry by method and URL pattern. It applies a typed `transform(body) => body` and fulfils with it. It throws if no entry matches. A synthetic body must start from a real one.
3. **Unit test** `scripts/tests/api-mock.test.js` (or `node --test` over a compiled helper, whichever pattern `npm run test:triage` uses): transform a fixture HAR entry and check that status and body are fulfilled and that a missing entry throws.
4. **Proof specs** (one test each): a 403 on one card endpoint shows the unauthorized card; an empty `simulations/search` shows the empty table text; a 500 on it shows the MFE error state; a 3 s delay shows `loading-overlay` and it then disappears.
5. **Guidance:** extend the "Mocked UI-contract specs" section from T9.1 with when to use which helper, and the rule that every synthetic body starts from a recorded one.

## 6. Acceptance criteria
- [ ] The four helpers exist, route on the context, log a `[MOCK]` step and return `unroute`.
- [ ] `mockFromHar` refuses to invent a body when no recorded entry matches.
- [ ] The four proof specs pass 3 times in a row with no retries.
- [ ] Section 2 lists the endpoint and state field for every ODM and empty state.

## 7. Review checklist (for `role-sdet-architect`)
- [ ] No helper uses `waitForTimeout`, and the delay comes from a timeout tier.
- [ ] Synthetic bodies are transforms of recorded entries, not hand-written JSON (except `mockStatus` error bodies).
- [ ] The unroute and cleanup path is used, so one test's mock can't leak into the next test in a serial file.

## 8. Risks and rollback
- **A mocked state that the backend can no longer produce** → T9.4's drift report flags fields that disappear from the recordings, and the matching synthetic test is reviewed then.
- **Leaking mocks across tests in a cached context** → each test unroutes in `afterEach`; the review checks it.

Rollback: delete the helper, its test and the proof specs.
