## 1. Problem
The first version of this task planned HAR-backed render specs for 12 card types, because about 30 tests were thought to check card data and to fail when INTEROP data changed. The 2026-11-05 nightly doesn't support that:
- The chart specs only check that a chart exists. They read no axes, legends or segment counts.
- Most chart data already comes from the static `lui/mockcards` service, so a HAR would be a mock of a mock.
- Line, Table and Tabbed fail because the view setup on shared `PSAutomation` changed. The phase rule says not to mock those failures away.

Mocking still helps in a few places: states that are hard to produce (Tree no-data and error), and live MaaS data (Maas Chart). This task now covers those. The view setup failures are a separate prerequisite.

## 8. Risks and rollback
- **The saved Tree view holds a different endpoint** (for example, from a real run that stopped early), so the route never matches → the test must assert the route was called, and fail rather than pass on live data.
- **The Tree view's saved endpoint:** DataSetup `UIDataReset/Test_008_SeedTreeCardEndpoints` saves it before the lanes start, so lane order doesn't matter. A run with `run-datasetup-first=false` relies on the value already saved. Until slice 1 merges, each nightly on `main` saves the bad endpoint again in old TC4.
- **Mocked and real lanes run at the same time on the same view** → mocked specs only read it. Real Test_014 TC2 saves the same endpoints the routes match.
- **A static chart breaks only on data shape** → still covered, because the real specs load `mockcards` every night.
- **The MaaS response isn't recordable** → slice 2 stops and gets re-planned.

Rollback: revert the slice's PR.
