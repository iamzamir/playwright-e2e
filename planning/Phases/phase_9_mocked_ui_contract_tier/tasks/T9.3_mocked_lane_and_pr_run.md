## 1. Problem
After T9.1 the mocked spec runs only by hand. It has to run every night as its own lane, so its results reach Allure, the triage dashboard and the verdict. It should also run on pull requests that touch page objects or Planning Space specs, so a locator change that breaks the mocked tests is caught before merge. That is the main value of a deterministic tier.

## 2. Evidence (verified 2026-10-27 on `main` @ `4d5cf28`)
- The PS UI workflow is `.github/workflows/playwright-ps-iop-ui-local-suite.yaml`. Its `build-matrix` job (lines 141–231) builds lanes from suite JSONs and a `folder_map`. Folders are listed explicitly, so `tests/PlanningSpace/Mocked/` is in no lane.
- `.github/workflows/pr-checks.yaml` runs type checks, lint, suite validation and the secrets scan. It runs no Playwright UI test and has no INTEROP secrets.
- The mocked tier still logs in for real and loads the portal and MFE from INTEROP (T9.1). So a PR run needs the same secrets and network access as the nightly (D7).

## 3. Scope
- **In:**
  - A `psmockedbatch` lane in the PS UI matrix. It runs `SUITENAME=PSMockedBatch`, with `PW_RETRIES=0` (a deterministic test that fails is a real failure), `--workers=3`, and the same report and verdict steps.
  - A path-filtered PR job, if D7 allows it: it runs on changes to `pageobjects/**`, `tests/PlanningSpace/**`, `util/har.util.ts`, `util/api-mock.util.ts` and `testdata/*/har/**`.
  - Allure label `tier=mocked` (`e2e` for the other lanes), so the Allure report can tell the tiers apart. On the triage dashboard, mocked tests are identified by their spec path (`PlanningSpace/Mocked/...`), which run-data records already carry. A dedicated tier column or filter on the dashboard is a follow-up, not part of this task.
- **Out:** the weekly record job (T9.4). Lane balancing for the real lanes (runtime plan Phase A).

## 4. Implementation steps
1. Add `"psmockedbatch": "PSMockedBatch"` to the matrix's suite list (follow how the existing suite lanes are added; `build-matrix` decides suite vs folder). Pass `PW_RETRIES=0` for this lane only.
2. In `configs/fixtures.ts` (or the Allure environment block in `playwright.config.ts`), add the label `tier=mocked` for specs under `tests/PlanningSpace/Mocked/`. Use `allure.label` in a fixture, keyed on `testInfo.file`.
3. **If D7 = yes:**
   - Add a `mocked-ui` job to `pr-checks.yaml`, with `paths` filters, `needs: checks`, the same login secrets as the PS nightly, `HEADLESS=true` and `npm run test:interop:mocked`.
   - Upload the Monocart report as an artifact.
   - Keep it optional, not a required branch-protection check, until it has been green on 10 PRs.
4. **If D7 = no:** nightly lane only. Record the decision in the master plan decision log.
5. Make sure the triage verdict treats this lane's failures as real: no known-issue entries for mocked tests.

## 8. Risks and rollback
- **INTEROP is down during a PR** → the job fails at login, not on a mock. The failure message comes from the login step, so it's clear. Keep the job optional.
- **Runner minutes** → path filters, and one job with 3 workers.

Rollback: remove the lane entry and the PR job.
