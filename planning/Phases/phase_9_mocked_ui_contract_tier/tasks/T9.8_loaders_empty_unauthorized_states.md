## 1. Problem
`pageobjects/planning/loaders-empty-states.component.ts` has locators for the "no baseline", "no views", "filter configure", loading overlay and unauthorized-card states. They are only reached when INTEROP happens to be in that state. No test can force them, so the states the user sees when something is wrong are not tested at all.

## 2. Evidence (verified 2026-10-27 on `main` @ `4d5cf28`)
- Learnings: `DynamicDashboardLoader.tsx` test-id prefixes `noBaselineAdmin`, `noBaselineUser`, `noViewsAdmin`, `noViewsUser` and `filterConfigure`; `loading-title`, `loading-overlay` and `error-action-links`; unauthorized card `lui-ccl-card-title`.
- `testervalue` (INTEROP) has views but no scenarios. That is the only real "no baseline" state, and only for one process.

## 3. Scope
- **In:** one mocked spec per state, for both admin and user where the UI differs:
  - no baseline: empty `simulations/search`
  - no views: empty views list
  - filter configure: empty filter config
  - loading: delayed data call
  - unauthorized card: 401 on `GET /process/<name>/context` (done in `Mocked/Unauthorized/Test_001`; verified in planning-mfe `useApi.tsx`, not a card endpoint)
  - error action links: 500
- **Out:** the ODM unified states (T9.6).

## 4. Implementation steps
1. For each state, find the call that decides it (T9.2 step 1 covers some; check `DynamicDashboardLoader.tsx` in `plan-sop-planning-mfe` for the rest). List them in section 2.
2. Write `tests/PlanningSpace/Mocked/Loaders/Test_001_LoaderAndEmptyStates.spec.ts`, one test per state, with `mockFromHar` or `mockStatus` from T9.2 and `unroute` in `afterEach`.
3. Assert the title, the action links and the button through the component's existing methods. Add POM methods where needed, not locators in the spec.
4. Registration and docs.
