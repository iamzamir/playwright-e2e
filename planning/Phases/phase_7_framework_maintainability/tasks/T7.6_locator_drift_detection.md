## 1. Problem
When the UI changes a test ID, label or structure, we find out only when a nightly test fails, usually after a minute-long wait. Converting XPath to stable locators (T7.2, T7.3) also needs the current markup each time, and today that means reading the UI source or writing a throwaway probe spec.

## 2. Evidence (2026-10-09, T7.2 slice 2)
- `docs/repositories/plan-sop-planning-mfe/ui-inventory.md` and `.../plan-sop-lui/ui-inventory.md` are maintained by hand (no generator under `scripts/`), last regenerated 2026-10-05.
- Many test IDs come from shared libraries, not the app source, so the inventories miss them: `lui-ccl-threedot-menu-*`, `lui-ccl-select-*`, `lui-ccl-modal` (`@jda/lui-common-component-library-mui5` 3.12.2), `lui-settings-ui-*` (`@by/lui-settings-ui-library` 1.2.5), `viewsList-*`, `tree-view`, `child-views` (`@by/plan-sop-ui-library` 2026.4.x). They are only readable from `plan-sop-lui/node_modules` (planning-mfe has no `node_modules`).
- Raw DOM is a poor diff source: MUI class names (`css-zlvivc`, `css-9o00i4`) change per build. `locator.ariaSnapshot()` of one region is small and stable, and maps straight to `getByRole` (it was enough to confirm every slice-2 locator in one 30 s probe).
- `npm run snapshot` (`scripts/save-snapshot.ts`) already writes a cleaned DOM and ARIA tree, but for the whole page, not inside the `mfe` iframe or for a region.

## 3. Scope
- **In, part A (static check):** `scripts/locators/check-test-ids.js` + `npm run locators:check`. Extract test IDs used in `pageobjects/**` (`getByTestId('…')`, `data-testid='…'`/`"…"` inside selectors, template prefixes such as `viewsList-${id}` as prefix matches) and compare with an inventory built from the UI repos **and** the shared library packages. Report: unknown IDs (likely broken), and with `--strict` exit 1. Add the library IDs to the inventories (or a generated `docs/repositories/libraries/test-ids.json`).
- **In, part B (nightly fingerprints):** a spec under `tests/DataSetupBatch/` (or a script) that opens the key Planning Space and PO states (view header, views drawer, view actions menu, Set Default Filter and Settings dialogs, left pane, scenario header…) and writes, per state, the region's ARIA snapshot and the list of `data-testid`s with values and free text stripped. Publish to gh-pages beside the triage run data (`fingerprints/<date>/<state>.yaml`), never to `main`. A diff step lists added or removed test IDs and roles per state, and the triage dashboard shows "changed since <date>".
- **In, small:** `npm run snapshot -- … --frame mfe --region <css|testid>` to capture inside the iframe for one region.
- **Out:** committing full DOM or screenshots to git (noise and repo growth; screenshots stay with the visual suite and CI artifacts).

## 4. Implementation steps
1. Part A: write the extractor and the inventory loader; unit tests with fixtures under `scripts/locators/tests/`; wire `locators:check` into `pr-checks` as non-blocking first, then blocking once the baseline is clean.
2. Part A: generate the library test-ID list from the packages in `plan-sop-planning-mfe/node_modules` and `plan-sop-lui/node_modules` (the libraries listed in section 2; grep `data-testid` / `dataTestId` defaults in `dist/*.js`, or the package's own `e2e` ID list where it has one), and record each package's version per repo in the file header. IDs that no local package contains (the portal command bar) go in a hand-kept allowlist with a source note.
3. Part B: define the state list in one JSON (`state`, `url or navigation helper`, `region locator`, `open steps` using existing POM methods only).
4. Part B: nightly workflow step after the PS UI run; push fingerprints to gh-pages; diff against the previous night; add a dashboard panel.
5. Learnings: where library test IDs come from and how to regenerate the list.

Part B: run the fingerprint job twice against INTEROP; the second diff is empty; renaming a test ID in a fixture shows up in the diff.

## 6. Acceptance criteria
- [ ] `npm run locators:check` lists every POM test ID missing from the inventories, with file and line.
- [ ] Library test IDs are part of the inventory, with package versions recorded.
- [ ] Nightly fingerprints are published to gh-pages and day-over-day changes are visible on the triage dashboard.
- [ ] No DOM dumps or screenshots committed to `main`.

## 7. Review checklist (for `role-sdet-architect`)
- [ ] Fingerprints contain no customer data, tokens or free text values.
- [ ] Navigation in the fingerprint job reuses POM methods (no inline selectors).
- [ ] False positives (dynamic test IDs) handled by prefix rules, not by suppressing the check.

## 8. Risks and rollback
- Inventory drift itself (hand-maintained files) → the generator in step 2 makes the library part reproducible; app-source part can follow the same approach.
- Rollback: remove the npm script and workflow step; no test code depends on it.
