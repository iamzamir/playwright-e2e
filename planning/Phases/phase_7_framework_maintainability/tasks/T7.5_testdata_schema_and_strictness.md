## 1. Problem
- `.github/instructions/testdata.instructions.md` requires a `_schema` block in test data JSON, but 254 of 402 files lack it (2026-10-26), so nobody can tell which keys a spec needs or which are environment-specific.
- `noImplicitAny: false` lets untyped parameters and variables through.
- 4 specs import `test` from `@playwright/test` instead of the repo fixtures. All four are Performance specs that launch their own browser, so this is a documented exception, not a migration.

## 2. Evidence (verified 2026-10-08 on `main` @ `f3d48bb`)
- `find testdata -name "*.json" -not -path "*/.auth/*" | wc -l` → 374; `grep -rl '"_schema"' testdata --include=*.json | wc -l` → 71.
- `tsconfig.json:7` `"noImplicitAny": false`; `strictNullChecks` already on.
- `grep -rlE "import \{[^}]*\btest\b[^}]*\} from '@playwright/test'" tests` → 4 files (the Performance specs use `chromium` directly; check whether they need the plain import).

### Now (2026-10-26, `main` @ `7415f6e`)
- **`_schema`:** 148 of 402 files. By folder: STAGE 37 of 37 (added with T7.4, all have it), INTEROP 69 of 209, QA 25 of 117, PSR 17 of 39. That leaves **254 files** to backfill.
- **`noImplicitAny`:** still `false`, but `npx tsc --noEmit -p tsconfig.json --noImplicitAny` reports only **3 errors in the whole project**:
  - `util/db.util.ts(1)` TS7016: no types for `mssql` (^11.0.1).
  - `tests/PlanningSpace/DuplicateView/Test_001_DuplicateViewProcess.spec.ts` lines 5 and 45, TS7034/TS7005: `indexOfTargetViewGroup` has no type.

  The "366 `: any` in specs" counted on 2026-10-08 are explicit annotations, and `noImplicitAny` doesn't flag those. They now stand at 315 in `tests/`, 108 in `util/`, 7 in `pageobjects/` and 4 in `configs/`. The second-tsconfig plan below was sized for hundreds of errors and is no longer needed.
- **Imports:** the same 4 files, all in `tests/Performance/`. Test_001 and Test_002 call `chromium.launch`; Test_003 and Test_004 call `PerformanceRunReporter.launchBrowserWithRetry`. None uses the `page` or `browser` fixture.
- **Validator:** nothing checks `_schema` yet. `scripts/validate-suites.js` covers suites and visual baselines. `pr-checks` already runs `npm run typecheck`.
- **Risk check:** no spec iterates over every top-level test data key. The only `Object.values(testData.X)` calls read nested objects (SupplyChainActionsBatch Test_006 `CHILD_VIEWS`, `PROCEDURE_DROPDOWN`), so adding `_schema` changes nothing at runtime.

Re-check: the commands above, from `playwright-e2e/`.

## 3. Scope
- **In:** (a) generate `_schema` blocks; (b) a validator check for `_schema`; (c) `noImplicitAny: true` in `tsconfig.json` for the whole project (3 errors to fix); (d) a header comment in each of the 4 Performance specs explaining the plain import.
- **Out:** reducing explicit `: any` (434 annotations). A lint rule with a baseline would track it; open a follow-up task if wanted.

## 4. Implementation steps
1. **Schema generator** `scripts/add-testdata-schema.js`: for each JSON without `_schema`, add `"_schema": { "<key>": "<type> (required)" }` for each top-level key (type from the value: string, number, boolean, array, object). Keep key order and indentation (2 spaces). Mark `REALM_NAME`, `PROCESS_NAME` and similar as required. Dry-run first and print the count.
2. Run it per environment folder, one commit each (INTEROP, QA, PSR; STAGE is already complete). Spot-check 10 files.
3. **Validator** (T2.3 script): new check, a test data JSON without `_schema` → ERROR for files added or changed in the PR, WARN otherwise. Built as ERROR for every file instead, because the backfill leaves none without it (see the progress log).
4. **Strictness:** set `"noImplicitAny": true` in `tsconfig.json`. Fix the 3 errors: add `@types/mssql` as a dev dependency (if the JFrog registry doesn't have it, use a small typed `declare module 'mssql'` with only the members `db.util.ts` uses), and give `indexOfTargetViewGroup` the type `number`. `npm run typecheck` already runs in `pr-checks`, so no new script or workflow step is needed.
5. **Imports:** keep `@playwright/test` in the 4 Performance specs, because they launch their own browser for timing. Add a one-line header comment to each one that says so.
