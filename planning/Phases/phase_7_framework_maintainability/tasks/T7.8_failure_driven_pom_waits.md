## 1. Problem
T7.2 and T7.3 set `.isVisible(` count targets per POM. The count doesn't track risk: many calls are legitimate instant absence probes, and the number went up (about 60 to about 70 in the five large POMs) while XPath and sleeps reached 0. What matters is the POM methods that fail in the nightly because an instant `isVisible()` was used where the test needed to wait or assert. This task fixes those, driven by triage data, not by a count.

## 3. Scope
- **In:** POM methods that appear in `AUTOMATION_ISSUE` or "to investigate" triage groups, or in T7.1's top ranking, where a check-style `isVisible()` is the cause; issues #873, #891, #893.
- **Out:** absence probes that work (an instant `isVisible()` inside `if` to decide an optional step is fine); count targets; signature changes.

## 4. Implementation steps
1. Take the top ranked methods and the open issues. For each one, read the failure evidence (trace, step trail, network log).
2. Sort each `isVisible()` call in the method:
   - The caller needs the element: use a web-first wait (`locator.waitFor` / `expect(...).toBeVisible()` with a `getTimeout` tier).
   - Optional UI that may or may not appear: a bounded `waitFor({ timeout: getTimeout('SHORT') })` probe with `.then(() => true, () => false)`, or keep the instant probe and say why.
3. Keep signatures; follow the POM rules (`.github/instructions/playwright-pom.instructions.md`).
4. Run the callers with `--repeat-each=3`. Note the issue number in the PR; close the issue when two nightlies pass.
