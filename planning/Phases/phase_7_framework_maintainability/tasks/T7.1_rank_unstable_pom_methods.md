## 1. Problem
491 XPath lines and 102 sleeps in six files is too much to fix at once. Fixing the methods that actually fail or flake each night pays back first.

## 2. Evidence (verified 2026-10-08 on `main` @ `f3d48bb`; re-checked 2026-10-09 @ `85f0858`)
- The dashboard run data (`dashboard/data/runs/<date>/*.json` on gh-pages) and Allure history hold failed steps with stack traces, and the step trail names POM methods (the `logMessage` steps).
- Failed records store `error.location = { file, line, function }`: the first stack frame in our code. 138 of 320 failures (43%) in the selected runs point into `pageobjects/`; the rest are `tests/` (144) or `util/` (38). No Allure fallback is needed for failures. Passing and flaky records carry no location.
- ~~30 nights of data exist~~ Re-check 2026-10-09: only **3 nights** of run data exist (2026-10-06 to 2026-10-08; the dashboard started publishing on 2026-10-06). The first ranking covers those 3 nights; `--days 30` picks up more as nights accumulate.

## 3. Scope
- **In:** `scripts/triage/rank-pom-methods.js`, which reads N nights of run data and outputs a ranked list of POM methods (file:method) by failure count, flaky count (passed on retry) and blocked tests caused. Plus the first ranking, committed as `planning/Phases/phase_7_framework_maintainability/pom-ranking-<date>.md`.
- **Out:** fixing the methods (T7.2, T7.3).

## 4. Implementation steps
1. Read the run data shape (triage plan §5.1–5.2, `scripts/triage/build-run-data.js`). Find where the failing location (stack frame in `pageobjects/*.page.ts`) is stored. If only the error message is stored, use the stack in the Allure result files from the run artifacts instead.
2. Extract `pageobjects/<file>.page.ts:<line>`, and map the line to the enclosing method name by parsing the file at the current `main` (a simple scan for `async <name>(` above the line is enough). Note lines that moved since the run as "approximate".
3. Count per method over the last 30 nights: failures, flaky passes, tests blocked after it (serial cascade).
4. Output Markdown: top 30 methods with counts, plus their XPath, sleep and `isVisible` counts (from the same scan). Columns: rank, file:method, failures, flaky, blocked, XPath, sleeps, `isVisible`.
5. Unit tests with two small run-data fixtures (`node:test`, alongside `scripts/triage/tests/`).
6. Add `"triage:rank-pom": "node scripts/triage/rank-pom-methods.js"` to `package.json`.
