## 1. Problem
Two shell bugs in `.github/workflows/playwright-po-backend-suite.yaml`:
1. **Single-batch path:** the ALM exclusion is built as a string and run as `$CMD`. Word splitting turns `--grep-invert="ALM Deploy Resource Migration"` into `--grep-invert="ALM` plus three extra arguments (`Deploy`, `Resource`, `Migration"`), which Playwright reads as file filters. The batch then runs nothing, or the wrong thing.
2. **All-batches path (`RUN_ALM_DEPLOY=false`):** six batches start with `&`, then a bare `wait` returns 0 whatever the children did. A crashed batch, one that writes no Allure results, isn't visible to the step.

## 2. Evidence (verified 2026-10-08 on `main` @ `f3d48bb`)

- Lines 249-265: six `PW_REPORT_TAG=<batch> npm run test:<env>:pobackend:<batch> &` followed by `wait`, for QA and for INTEROP.

## 4. Implementation steps
1. **Read `scripts/run-po-backend-batches-parallel.js`.** If it runs the same six batches and reports a non-zero exit when one fails, prefer routing both paths through it: add `--grep-invert <text>` (passed through to each `npm run ... -- --grep-invert <text>`) and an `--exclude-alm` shortcut. Then the `RUN_ALM_DEPLOY=false` path becomes `node scripts/run-po-backend-batches-parallel.js --env "$TEST_ENV" --exclude-alm`, with no duplicated batch list in YAML.
2. **If you keep the shell instead**, collect PIDs and exit codes:
   ```bash
   declare -A PIDS=()
   for b in actionitem calendar linkmanagement migration processbatch uifields; do
     args=()
     [[ "$b" == "migration" ]] && args=(-- --grep-invert "ALM Deploy Resource Migration")
     PW_REPORT_TAG="$b" npm run "test:${ENV_KEY}:pobackend:${b}" "${args[@]}" &
     PIDS[$b]=$!
   done
   FAILED=()
   for b in "${!PIDS[@]}"; do
     wait "${PIDS[$b]}" || FAILED+=("$b")
   done
   echo "batches_failed=${FAILED[*]}" >> "$GITHUB_OUTPUT"
   [[ ${#FAILED[@]} -eq 0 ]] || { echo "::warning::Batches with non-zero exit: ${FAILED[*]}"; exit 1; }
   ```
   Keep `continue-on-error: true` on the step, so the report and verdict still run. Give the step an `id` (for example `tests_all`) so T1.4 can read `steps.tests_all.outcome`.
3. **Single-batch path:** build the command as an array.
   ```bash
   CMD=(npm run "test:${ENV_KEY}:pobackend:${BATCH_SCRIPT}")
   if [[ "${RUN_ALM_DEPLOY}" == "false" ]]; then
     CMD+=(-- --grep-invert "ALM Deploy Resource Migration")
   fi
   printf 'Executing: %q ' "${CMD[@]}"; echo
   "${CMD[@]}"
   ```
   Also validate `BATCH_SCRIPT` against the known list before running, so a typo in the dispatch input fails with a clear message rather than `npm ERR! missing script`.
4. Keep the `node scripts/strip-allure-traces.js` call after the batches in both paths.
5. Pass the failed-batch list to the Teams card or job summary if it's easy (one line in the existing summary step); otherwise leave it in the step output for T1.4.
