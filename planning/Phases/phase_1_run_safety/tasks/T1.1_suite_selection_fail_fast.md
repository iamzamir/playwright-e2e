## 1. Problem
When `SUITENAME` names a file that doesn't exist, `loadTestSuite()` returns `['**/**.spec.ts']` and every spec runs, the destructive DataSetup specs included. `setup.js` makes this the default by setting `SUITENAME` to suites that were never created. A hard-coded `specificTests` list in the committed config also decides what runs whenever a local `.env` sets `USE_SPECIFIC_TESTS=true`.

## 2. Evidence (verified 2026-10-08 on `main` @ `f3d48bb`)
- `playwright-e2e/configs/playwright.config.ts:7-42`: `loadTestSuite()`. Missing file → falls through to line 41 `return ['**/**.spec.ts'];`. Lines 11-23: committed `specificTests` array with one active entry (`ProcessOrchestration/ScopeBatch/Test_003_SaveAndDeleteFilterInSettings.spec.ts`).
- `playwright-e2e/configs/setup.js:48`: `process.env.SUITENAME = process.env.SUITENAME || (environment === 'QA' ? 'complete-qa-suite' : 'complete-iop-suite');`. Neither file exists in `tests/TestSuites/`.
- `playwright-e2e/package.json:13`: `test:interop:poui` sets `SUITENAME=POUIInterop`, which doesn't exist. The PO UI workflow uses the `test:interop:poui:<batch>` scripts instead (`.github/workflows/playwright-po-iop-ui-local-suite.yaml:160-162`).
- `.github/workflows/playwright-ps-iop-ui-local-suite.yaml:368`: folder mode runs `env -u SUITENAME ... npx playwright test <folder>`. That works today only because the fallback returns every spec and the CLI folder narrows it. **Removing the fallback without also removing the `setup.js` default would break folder mode.**
- Disabled legacy workflows use `SUITENAME=failed-qa-suite` (`complete-qa-suite.yaml:137`, `po-qa-suite.yaml:136`). They're disabled and out of scope (T8.1).

## 4. Implementation steps
1. **Remove the dead default** in `configs/setup.js:48`. Delete the line. No `SUITENAME` now means "no suite: use the CLI path or filters".
2. **Rewrite `loadTestSuite()`** in `configs/playwright.config.ts`:
   ```ts
   const SUITES_DIR = path.join(__dirname, '../tests/TestSuites');

   function listSuites(): string[] {
     return fs.readdirSync(SUITES_DIR).filter((f) => f.endsWith('.json')).map((f) => f.replace(/\.json$/, '')).sort();
   }

   function loadTestSuite(): string[] {
     const suiteName = (process.env.SUITENAME || '').trim();
     if (process.env.USE_SPECIFIC_TESTS === 'true') {
       return loadSpecificTests();
     }
     if (!suiteName) {
       return ['**/*.spec.ts'];
     }
     const suiteFilePath = path.join(SUITES_DIR, `${suiteName}.json`);
     if (!fs.existsSync(suiteFilePath)) {
       throw new Error(`Suite "${suiteName}" not found at ${suiteFilePath}. Available suites: ${listSuites().join(', ')}. Unset SUITENAME to run by path.`);
     }
     const files: string[] = JSON.parse(fs.readFileSync(suiteFilePath, 'utf-8')).testFiles || [];
     if (files.length === 0) {
       throw new Error(`Suite "${suiteName}" has no testFiles.`);
     }
     return files.map((file) => file.replace(/^\*\*\/playwright-e2e\/tests\//, '**/'));
   }
   ```
   - Don't wrap the parse in `try/catch`. A malformed suite JSON must fail loudly too.
   - Keep the existing `console.log` lines for suite name and `USE_SPECIFIC_TESTS`; the triage scripts and people read them in CI logs.
3. **Move `specificTests` out of the config.** Add `loadSpecificTests()`:
   - It reads `process.env.SPECIFIC_TESTS` (comma-separated globs). If that's empty, it reads the gitignored file `configs/specific-tests.local.json` (`{ "testFiles": [...] }`). If both are empty, it throws `USE_SPECIFIC_TESTS=true but neither SPECIFIC_TESTS nor configs/specific-tests.local.json lists any spec.`
   - Add `configs/specific-tests.local.json` to `playwright-e2e/.gitignore`. Commit `configs/specific-tests.example.json` with one commented example spec path in a `_comment` field.
   - Delete the `specificTests` array from `playwright.config.ts`.
4. **Fix `test:interop:poui`** in `package.json:13`. Recommended: delete it, because the workflow and the README use the `test:interop:poui:<batch>` scripts. If someone needs one command for all PO UI, use `cross-env ... npx playwright test tests/ProcessOrchestration --config=configs/playwright.config.ts`, with the `TEST_IGNORE` list used by `test:interop:poui:other`.
5. **`test:interop`, `test:qa`, `test:psr`** now run every spec by path. That's still dangerous until T1.2 lands, so ship T1.1 and T1.2 back to back, or add a temporary note to the README.
6. **README** (`playwright-e2e/README.md:266`): update the `USE_SPECIFIC_TESTS` row, and add rows for `SUITENAME` ("unknown name fails fast") and `SPECIFIC_TESTS`.
7. Note in `.agents/learnings.md`: replace the "An unknown `SUITENAME` ... silently falls back" line under "Playwright framework" with the new behaviour.

- A person or script relying on "no suite = everything + implicit default" gets a different selection → the README and the PR description state the change; T1.2 makes the no-suite path safe.

- Rollback: revert the PR; no data or workflow state changes.
