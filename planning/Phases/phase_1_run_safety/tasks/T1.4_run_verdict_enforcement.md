## 1. Problem
Every Playwright test step has `continue-on-error: true`, so test failures never fail a job. The triage work added a "Run Verdict" job to the three functional workflows, and it's the agreed replacement for "fail the job when a test fails": red only when there are unexplained failures or the run is broken. But `PW_VERDICT_MODE` isn't set, so it only reports. The visual, performance and custom-tests workflows have no verdict at all and always finish green.

## 3. Scope

## 4. Implementation steps
**Part A: evidence for D1 (no code)**
1. For the last 10 nights of each functional suite, download the `triage-verdict` artifact (`gh run list --workflow <file> --limit 15`, then `gh run download <id> --name triage-verdict`). Tabulate: date, suite, verdict, unexplained count, and whether each unexplained failure was a real new problem.
2. Add the table to this task's progress log and propose a switch date. The rule from D1: switch when 10 consecutive nights have no red verdict caused by a missing registry entry. Until then, fill `triage/known-issues.json` and `triage/quarantine.json` (use `npm run triage:suggest`).
3. When the user agrees, they (or an admin) set the variable: `gh variable set PW_VERDICT_MODE --body enforce`. Record the date in the master plan decision log. The variable applies to all three functional workflows; to stage it, temporarily read a per-workflow variable (`vars.PW_VERDICT_MODE_PS_UI || vars.PW_VERDICT_MODE || 'report'`).

**Part B: visual workflow**
4. In `visual-automation-test.yaml`, give the "Run Visual Tests" step `id: tests`. In `generate-report`, after Allure results are downloaded, add a "Compute Run Verdict" step copied from the PS workflow (lines ~511-531) with `--suite VISUAL-<VISUAL_SUITE>`, `--check-count false` (suites change size often), and `--upstream-result ${{ needs.run-tests.result }}`.
5. Add a `run-verdict` job like the PS one, reading `PW_VERDICT_MODE_VISUAL` (default `report`). Visual diffs are expected after intended UI changes, so start it in report mode and decide separately.

**Part C: performance and custom tests**
6. These have no known-issue model. Add a final step to the test job:
   ```yaml
   - name: Fail run if tests failed
     if: always() && steps.tests.outcome == 'failure' && vars.PW_OUTCOME_GATE == 'enforce'
     run: |
       echo "::error title=Tests failed::See the Allure report for this run."
       exit 1
   ```
   Give the test step `id: tests`. If reports are deployed by a later job, put the gate in a final job with `needs: [<test job>, deploy-pages]` and `if: always()`, so the report still publishes.
7. Custom tests are dispatched by a person who looks at the result, so enforce there by default: `vars.PW_OUTCOME_GATE != 'report'`.

**Part D: document**
8. Add a "Run status" section to `playwright-e2e/README.md` (or the triage plan §4.1): which workflows use the verdict and which the outcome gate, the variables, and how to switch. Update the learnings line about `continue-on-error`.
