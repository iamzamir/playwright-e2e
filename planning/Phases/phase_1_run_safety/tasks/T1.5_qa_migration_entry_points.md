## 1. Problem
#1019 made the PO backend workflow skip the migration batch on QA, because migration isn't supported there: `Migration/Test_009_ALMDeployResourceMigration` has no QA test data, so the whole batch fails at load. Two local entry points still ran it: `npm run test:qa:pobackend:parallel` (through `scripts/run-po-backend-batches-parallel.js`) and `npm run test:qa:pobackend:migration`. A local QA run therefore failed for a reason the nightly had already ruled out.

## 2. Evidence (verified 2026-11-11 on `origin/main` @ `339751f`)
- `.github/workflows/playwright-po-backend-suite.yaml` lines 332–336 (all batches) and 395–396 (one batch) skip or refuse migration on QA.
- `scripts/run-po-backend-batches-parallel.js` listed `${prefix}:migration` for both environments.
- `package.json` `test:qa:pobackend:migration` ran `tests/ProcessOrchestrationBackend/Migration` on QA.
- `testdata/QA/ProcessOrchestrationBackend/Migration/` holds 8 of the 9 specs' files (no `Test_009`).

Re-check:
```bash
cd playwright-e2e
grep -n "migration" scripts/run-po-backend-batches-parallel.js
node -e "console.log(require('./package.json').scripts['test:qa:pobackend:migration'])"
ls testdata/QA/ProcessOrchestrationBackend/Migration
```

## 3. Scope
- **In:** the parallel runner, the QA migration npm script, the README section on parallel batches.
- **Out:** creating QA migration test data (that needs a decision that QA should support migration, not invented tenant data).

## 4. Implementation steps
1. The parallel runner builds its batch list from names and drops `migration` when `ENVIRONMENT=QA`, printing why.
2. `test:qa:pobackend:migration` becomes a stub that prints "Migration tests are not supported on QA … run test:interop:pobackend:migration" and exits 1, so anyone calling it gets the reason rather than a load error.
3. README "Parallel PO Backend Batches": six batches (UI Fields was missing from the list), and the QA skip.

## 5. Verification
```bash
cd playwright-e2e
npm run test:qa:pobackend:migration; echo $?    # prints the reason, exits 1
node --check scripts/run-po-backend-batches-parallel.js
npm run validate:suites
```
