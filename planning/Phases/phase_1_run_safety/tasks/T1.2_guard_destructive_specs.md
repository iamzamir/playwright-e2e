## 1. Problem
Every spec under `tests/DataSetupBatch/` changes or deletes shared data: processes, scenarios, view mappings, calendars, planning instances, feature toggles. Any run without a suite (after T1.1, `npm run test:interop` or a broad `npx playwright test`) picks them up. Nothing stops them except people remembering not to.

## 2. Evidence (verified 2026-10-08 on `main` @ `f3d48bb`)
- 19 specs under `playwright-e2e/tests/DataSetupBatch/{ODM,ProcessOrchestration,Scenarios,UIDataReset}`. 9 are in `tests/TestSuites/DataSetup.json`; 10 are in no suite.
- The four `DeleteAll*` specs (`ProcessOrchestration/Test_004_DeleteAllViewMappings`, `Test_005_DeleteAllCalendars`, `Test_006_DeleteAllAssumptionKpis`, `Test_007_DeleteAllSupplyChainActions`) authenticate with `REALM_CLIENT_ID_TARGET` / `REALM_ID_TARGET` (the migration target realm) and have no name filter or dry run.
- `ODM/Test_001_DeletePIanningInstances`, `Scenarios/Test_001_DeleteScenarios` and `UIDataReset/Test_003_CleanupProcess` are also unregistered and destructive.
- The only workflow that runs DataSetup on purpose: `.github/workflows/playwright-ps-iop-ui-local-suite.yaml:258-268` (`SUITENAME=DataSetup ... --workers=2`).
- `playwright-custom-tests.yaml` accepts any path, so it can run a DataSetup folder.

## 3. Scope
- **In:** a config-level guard for `DataSetupBatch`, a second in-spec guard for the four `DeleteAll*` specs, the DataSetup workflow step, an input on the custom-tests workflow, and docs.
- **Out:** making the deletes narrower (T4.5); deleting specs (decision D5 says keep them).

## 4. Implementation steps
1. **Config guard** in `configs/playwright.config.ts`, next to the existing `testIgnore` (around line 47):
   ```ts
   const allowDestructive = (process.env.ALLOW_DESTRUCTIVE || '').toLowerCase() === 'true';
   if (!allowDestructive) {
     testIgnore.push('**/DataSetupBatch/**');
   }
   console.log(`Destructive DataSetup specs: ${allowDestructive ? 'ENABLED (ALLOW_DESTRUCTIVE=true)' : 'excluded'}`);
   ```
   `testIgnore` applies even when a spec path is passed on the command line, so a direct `npx playwright test tests/DataSetupBatch/...` without the flag runs nothing. Confirm this with the verification below.
2. **Fail loudly instead of silently running nothing.** If `SUITENAME=DataSetup` is set without `ALLOW_DESTRUCTIVE=true`, throw at config load: `SUITENAME=DataSetup requires ALLOW_DESTRUCTIVE=true.`
3. **Second guard in the four `DeleteAll*` specs.** At the top of each `test.beforeAll`:
   ```ts
   if (process.env.ALLOW_DESTRUCTIVE !== 'true' || !process.env.REALM_ID_TARGET) {
     throw new Error('Refusing to delete: set ALLOW_DESTRUCTIVE=true and REALM_ID_TARGET (migration target realm only).');
   }
   ```
   Make it a small shared helper, `assertDestructiveRunAllowed(realmEnvKey: string)`, in `util/alm-migration.util.ts` (the specs already import from it) rather than four copies.
4. **Workflow:** in `.github/workflows/playwright-ps-iop-ui-local-suite.yaml`, the "Run DataSetup Tests" step (line ~258), add `ALLOW_DESTRUCTIVE: 'true'` to its `env:`. No other step gets it.
5. **Custom tests workflow:** add a boolean `workflow_dispatch` input `allow-destructive` (default `false`) to `playwright-custom-tests.yaml` and pass it as `ALLOW_DESTRUCTIVE` to the test step only. Describe it as: "Allow DataSetupBatch specs (they modify or delete shared data)".
6. **Docs:** add `ALLOW_DESTRUCTIVE` to the env-var table in `playwright-e2e/README.md`. Add a line to `.github/instructions/playwright-specs.instructions.md`: new specs that delete shared data belong in `DataSetupBatch/` and must use `assertDestructiveRunAllowed`.

## 8. Risks and rollback
- The nightly DataSetup job loses the flag in a later workflow refactor (T5.3) → T5.3's review checklist includes it.
- Someone sets `ALLOW_DESTRUCTIVE=true` in a local `.env` and forgets it → the config prints a loud line when it's enabled; the README warns against keeping it in `.env`.
- Rollback: revert the PR.
