## 1. Problem
Third-party actions run with repository secrets (gh-pages token, Teams webhook) and are referenced by mutable tags, so a retagged release changes what runs. There are no Dependabot version updates for actions or npm, no PR template that reminds authors of the Definition of Done, and the new `pr-checks` isn't required.

## 2. Evidence (verified 2026-10-08 on `main` @ `f3d48bb`)
- `peaceiris/actions-gh-pages@v3` used about 10 times (one place already uses SHA `4a2e02b…`); `aliencube/microsoft-teams-actions@v0.8.0` twice. GitHub-owned actions (`actions/checkout`, `setup-node`, `upload-artifact`, ...) are also tag-pinned.
- `.github/dependabot.yml` doesn't exist. Only GitHub's default security updates run (`dynamic/dependabot/dependabot-updates`).
- `.github/pull_request_template.md` doesn't exist. `.github/CODEOWNERS` assigns `*` to `@BY-Product-Development/cbp-planning-space-owners-admins`.
- `peaceiris/actions-gh-pages@v3` runs on an old Node runtime; check its deprecation warnings in a recent run log.

Re-check:

## 3. Scope
- **In:** SHA-pin every `uses:` (third-party first), upgrade `peaceiris/actions-gh-pages` to v4, add `dependabot.yml`, add a PR template, and give the admin the branch-protection request.
- **Out:** restructuring workflows (T5.x).

## 4. Implementation steps
1. **Pin.** For each distinct action and version: `gh api repos/<owner>/<repo>/git/ref/tags/<tag> --jq .object.sha` (dereference annotated tags with `gh api repos/<owner>/<repo>/git/tags/<sha> --jq .object.sha`). Replace with `uses: owner/repo@<sha> # vX.Y.Z`. Do it in one commit per action, so a bad pin is easy to revert.
2. **Upgrade** `peaceiris/actions-gh-pages` v3 → v4 (read its release notes; inputs are compatible for `publish_dir`, `destination_dir`, `keep_files`, `github_token`). Do the gh-pages-publishing workflows one at a time, and dispatch each once on the branch. Ask the user first, because it publishes to the shared gh-pages report site. Publish under a scratch `destination_dir` for the test if possible.
3. **`aliencube/microsoft-teams-actions`:** check whether it's still maintained. If not, replace it with a `curl` POST of the existing card JSON to the webhook (the workflows already build card JSON for other steps). Note the choice in the PR.
4. **`.github/dependabot.yml`:**
   ```yaml
   version: 2
   updates:
     - package-ecosystem: github-actions
       directory: /
       schedule: { interval: weekly }
       groups: { actions: { patterns: ['*'] } }
     - package-ecosystem: npm
       directory: /playwright-e2e
       schedule: { interval: weekly }
       open-pull-requests-limit: 5
       groups:
         playwright: { patterns: ['@playwright/*', 'playwright*', 'allure-*', 'monocart-*'] }
         dev-tooling: { patterns: ['eslint*', 'typescript*', '@types/*', 'typescript-eslint'] }
   ```
   Don't add `/e2e` (being retired, T8.1). If npm resolves through JFrog, Dependabot needs a registry entry with a secret. Ask the admin; if that isn't possible, keep only the `github-actions` ecosystem.
5. **PR template** `.github/pull_request_template.md`: task id (`T<P>.<N>` or "n/a"); what changed; how it was verified (commands, run links); a Definition of Done checklist mirroring `workflow.instructions.md` (typecheck, lint, suites, docs regenerated, spec run in isolation); a "Risks / rollback" line.
6. **Branch protection (D4):** write the exact request for the repo admin: require the status checks `pr-checks / checks` and `pr-checks / secrets-scan` on `main`, after `pr-checks` has been green on 5 PRs. Record who did it and when in the master plan decision log.
