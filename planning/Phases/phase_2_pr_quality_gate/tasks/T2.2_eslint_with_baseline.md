## 1. Problem
The written conventions (no XPath, no `waitForTimeout`, awaited Playwright calls, no focused tests) aren't enforced. Turning them on as errors today would fail hundreds of existing lines, so the gate must fail only on **new** violations while the old ones are paid down in Phase 7.

## 3. Scope
- **In:** ESLint flat config, plugins, rules, a baseline mechanism, `lint` and `lint:baseline` scripts.
- **Out:** fixing the existing violations (T7.x, T3.3); running lint in CI (T2.4).

## 4. Implementation steps
1. **Packages** (devDependencies; confirm each resolves from the JFrog registry first with `npm view <pkg> version`): `eslint@^9`, `typescript-eslint`, `eslint-plugin-playwright`.
2. **`playwright-e2e/eslint.config.mjs`** (flat config):
   ```js
   import tseslint from 'typescript-eslint';
   import playwright from 'eslint-plugin-playwright';

   const XPATH = "Literal[value=/^\\(?\\/\\//], TemplateElement[value.raw=/^\\(?\\/\\//], Literal[value=/^xpath=/]";

   export default tseslint.config(
     { ignores: ['node_modules/**', 'reports/**', 'test-results/**', 'dashboard/**', 'scripts/**/*.js'] },
     {
       files: ['**/*.ts'],
       languageOptions: { parser: tseslint.parser, parserOptions: { project: './tsconfig.json' } },
       plugins: { '@typescript-eslint': tseslint.plugin, playwright },
       rules: {
         'playwright/no-wait-for-timeout': 'error',
         'playwright/missing-playwright-await': 'error',
         'playwright/no-focused-test': 'error',
         'playwright/no-skipped-test': ['warn', { allowConditional: true }],
         '@typescript-eslint/no-floating-promises': 'error',
         'no-restricted-syntax': ['error', { selector: XPATH, message: 'XPath is banned (copilot-instructions.md). Use getByRole/getByTestId/getByLabel.' }]
       }
     }
   );
   ```
   Check that the XPath selector catches the patterns used in this repo (`'//div[...]'`, `"(//li)[1]"`, template literals, `xpath=`) and doesn't flag URLs (`'https://...'` starts with `h`, so it's safe) or comments. Write three small fixture snippets and run ESLint on them.
3. **Baseline.** Use ESLint's suppressions file if the installed version supports it (`eslint --suppress-all` writes `eslint-suppressions.json`; new violations fail, fixed ones must be pruned with `--prune-suppressions`). If it isn't available, write `scripts/lint-baseline.js`:
   - Run ESLint **through its Node API** (`new ESLint({ cwd })` then `lintFiles(['.'])`), or spawn `eslint . --format json` and read stdout **whatever its exit code is**. Legacy violations are configured as errors, so the ESLint CLI exits 1 on the current baseline. The wrapper must not treat that exit code as failure.
   - Treat these as real failures, separate from rule violations: a fatal parse error (`message.fatal === true`), a config error, or ESLint not producing JSON.
   - Count violations per `file + ruleId` and compare against the committed `lint-baseline.json`. The **wrapper's own exit code** decides the result: 1 if any `file + ruleId` count went up, a file not in the baseline has violations, or there was a fatal error; otherwise 0. Print the improvements, and tell the author to run `npm run lint:baseline` to lock them in.
   - `lint:baseline` uses the same collection path and writes the counts. It never fails on violations, only on fatal errors.
4. **Scripts:**
   - With suppressions: `"lint": "eslint ."` and `"lint:baseline": "eslint . --suppress-all"` (suppressed violations don't affect the exit code).
   - With the custom baseline: `"lint": "node scripts/lint-baseline.js --check"` and `"lint:baseline": "node scripts/lint-baseline.js --write"`. Never `eslint . && <compare>`: with the legacy errors present, `&&` stops before the comparison runs, so `npm run lint` could never pass.
5. **Record the starting numbers** per rule in the PR description and in the master plan baseline table (they become the Phase 7 targets).
6. **Fix what's cheap:** `missing-playwright-await` and `no-floating-promises` findings are real bugs (un-awaited actions). Fix them in this PR if there are fewer than about 20; otherwise baseline them and open a follow-up task.
7. Add "Run `npm run lint` before committing" to `.github/instructions/workflow.instructions.md` (Definition of Done).

## 7. Review checklist (for `role-sdet-architect`)
- [x] The XPath rule has no false positives on URLs, paths or comments (check the fixture snippets).
- [x] No rule is turned off globally to make the run pass; only the baseline absorbs existing violations.
- [x] The baseline is keyed per file and rule, not one global number (a global number lets new violations hide behind fixed ones).

## 8. Risks and rollback
- Type-aware linting is slow on a big repo → if `npm run lint` takes over 3 minutes, drop `no-floating-promises` to a separate, path-limited run.
- JFrog doesn't have a package version → pin to the version that is available.
- Rollback: remove the config and scripts; nothing else depends on them until T2.4.
