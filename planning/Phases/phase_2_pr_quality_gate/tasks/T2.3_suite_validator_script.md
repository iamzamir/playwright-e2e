## 1. Problem
Which specs run in CI is spread across suite JSONs, npm folder scripts, `TEST_IGNORE` lists, a workflow `folder_map` and visual suite JSONs. Nothing checks that these point at real files, or that every spec is covered by one of them. PR #734 showed the failure mode: a visual suite listed a spec with no baseline, and the catalog listed deleted specs.

## 2. Evidence (verified 2026-10-08 on `main` @ `f3d48bb`)
- 237 specs; 57 match no suite JSON (13 Planning Space, 29 PO UI, 10 DataSetup, 4 Performance, 1 Visual). The PO UI ones are run by folder through `package.json` `test:interop:poui:*` scripts.
- Suite JSON entries are globs in two styles: `**/playwright-e2e/tests/...` (most) and `tests/...` (`PSSmokeBatch.json`). Both resolve today (`PSSmokeBatch` lists 32 tests in 9 files).
- Other places that select specs: `package.json` scripts (folder paths, `TEST_IGNORE=`, `SUITENAME=`); `.github/workflows/playwright-ps-iop-ui-local-suite.yaml` `folder_map` (no `AddLanePopup` entry) and its suite matrix (`suite_name`); `visual-automation-test.yaml` `visual-suite` options; `tests/VisualAutomation/VisualSuites/*.json`.
- A working prototype of the glob matching (tested on 2026-10-08) is in the "Prototype" section below.

Re-check: run the prototype from `playwright-e2e/`.

## 3. Scope
- **In:** `scripts/validate-suites.js`, an allow-list file, an npm script, and a `--json` report for T6.1.
- **Out:** fixing what it reports (T6.1); running it in CI (T2.4).

## 4. Implementation steps
1. Create `playwright-e2e/scripts/validate-suites.js` (CommonJS, no new dependencies, matching the other scripts). Checks, each reported as `ERROR` or `WARN`:
   | Check | Level |
   |---|---|
   | Every entry in `tests/TestSuites/*.json` and `tests/VisualAutomation/VisualSuites/*.json` matches at least one spec file | ERROR |
   | Every `SUITENAME=<name>` in `package.json` exists in `tests/TestSuites/` | ERROR |
   | Every `suite_name` in the PS workflow matrix exists; every `folder_map` path exists | ERROR |
   | Every `visual-suite` option in `visual-automation-test.yaml` exists in `VisualSuites/` | ERROR |
   | Every `TEST_IGNORE=` path in `package.json` exists | ERROR |
   | Every spec is covered by a suite, a folder used by an npm script or the `folder_map`, or the allow-list | ERROR for new specs, WARN for those listed in the allow-list |
   | Every visual suite entry has a committed baseline (`testdata/INTEROP/VisualBaseValidations/<testFileDir>/<name>.png` for each `validatePage`/`validateArea` name in the spec) | WARN at first (name extraction by regex is approximate) |
2. Glob matching: reuse the prototype's converter (handle `**/` before `*`, as the prototype does). Normalise Windows paths to `/`.
3. YAML: don't add a YAML parser. Extract `folder_map` paths, `suite_name` values and `visual-suite` options with targeted regexes, and fail with a clear message if the expected block isn't found (so a workflow refactor can't silently disable the check).
4. **Allow-list:** `playwright-e2e/tests/TestSuites/_unscheduled.json`:
   ```json
   { "_schema": { "specs": "spec path relative to tests/ → reason it runs outside any suite or schedule" },
     "specs": { "DataSetupBatch/ProcessOrchestration/Test_005_DeleteAllCalendars.spec.ts": "Destructive, migration target realm; manual only (T1.2)" } }
   ```
   Seed it with the 57 current specs, each with a short reason, or `"TODO T6.1"` where nobody knows yet. T6.1 removes the TODOs. Make sure `loadTestSuite()` never treats `_unscheduled` as a runnable suite (T1.1 lists `*.json`, so skip names starting with `_`).
5. Output: a readable table plus `--json` (`{ errors: [], warnings: [], unregistered: [] }`). Exit 1 on any ERROR.
6. `package.json`: `"validate:suites": "node scripts/validate-suites.js"`.
7. Unit tests: add `scripts/tests/validate-suites.test.js` using `node:test` (the triage tests use the same runner), with small temp-folder fixtures covering each check.

### Prototype (glob matching, verified 2026-10-08)
```js
const esc = s => s.replace(/[.+^${}()|[\]\\]/g, ch => '\\' + ch);
const toRe = g => new RegExp('^' + esc(g)
  .replace(/\*\*\//g, '\u0001').replace(/\*\*/g, '\u0002').replace(/\*/g, '[^/]*')
  .replace(/\u0001/g, '(?:.*/)?').replace(/\u0002/g, '.*') + '$');
// match against the absolute spec path with "/" separators; for "tests/..." entries, prefix "**/"
```
