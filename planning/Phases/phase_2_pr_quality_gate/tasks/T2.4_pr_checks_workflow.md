## 1. Problem
Nothing runs on a pull request apart from GitHub's managed CodeQL and Copilot review. Type errors, lint violations, broken suites, a stale `docs/testcases` catalog and broken triage scripts all reach `main` unnoticed.

## 2. Evidence (verified 2026-10-08 on `main` @ `f3d48bb`)
- `grep -l pull_request .github/workflows/*.yaml` finds nothing.
- `npm run test:triage` (`node --test scripts/triage/tests/*.test.js`) isn't called by any workflow.
- `scripts/generate-testcase-docs.js` writes a `Generated:` timestamp into every file, so a plain `git diff --exit-code` after regenerating would always fail. The drift check must ignore that line.
- Workflows install from JFrog ("Authenticate with npm (JFrog)" step), and runners are self-hosted labels such as `az-prod-ubuntu-latest-8Core`. Copy the setup steps from an existing workflow (for example `visual-automation-test.yaml:103-127`).

Re-check:
```bash
grep -ln "pull_request" .github/workflows/*.yaml
grep -rn "test:triage" .github/workflows
grep -n "Generated" playwright-e2e/scripts/generate-testcase-docs.js | head -3
```

## 3. Scope
- **In:** `.github/workflows/pr-checks.yaml`, a catalog drift script, and a gitleaks step.
- **Out:** making the check required (T2.5); running real tests on PRs (too slow and needs environments; `--list` only).

## 4. Implementation steps
1. **Catalog drift script** `playwright-e2e/scripts/check-testcase-docs.js`: run the generator into a temp dir (add an `--out <dir>` option to `generate-testcase-docs.js` if it lacks one), strip lines matching `/\*\*Generated:\*\*/` and the generated-date column in the CSV, if any, and compare with `docs/testcases/`. Exit 1 with "Run `npm run docs:testcases` and commit the result" on any difference. Add `"docs:testcases:check"` to `package.json`.
2. **Workflow** `.github/workflows/pr-checks.yaml`:
   ```yaml
   name: pr-checks
   on:
     pull_request:
       branches: [main]          # no `paths` filter: see the note below the block
   concurrency: { group: pr-checks-${{ github.event.pull_request.number }}, cancel-in-progress: true }
   permissions: { contents: read }
   jobs:
     checks:
       runs-on: [az-prod-ubuntu-latest-8Core]   # same label as other jobs; confirm with the team
       timeout-minutes: 20
       defaults: { run: { working-directory: playwright-e2e } }
       steps:
         - uses: actions/checkout@<sha>        # with fetch-depth: 0 for gitleaks
         - uses: actions/setup-node@<sha>      # node-version: '24.x', cache: npm
         - name: Authenticate with npm (JFrog)  # copy from an existing workflow
         - run: npm ci
         - run: npm run typecheck
         - run: npm run lint
         - run: npm run validate:suites
         - run: npm run docs:testcases:check
         - run: npm run test:triage
         - name: List tests (functional config, no suite)
           run: npx playwright test --config=configs/playwright.config.ts --list > /dev/null
           env: { PW_ENABLE_GLOBAL_SETUP: 'false', USE_SPECIFIC_TESTS: 'false', ENVIRONMENT: INTEROP }
         - name: List tests (visual config)
           run: npx playwright test --config=configs/playwright.visual.config.ts --list > /dev/null
           env: { VISUAL_SUITE: CompleteSmokeVisual, PW_ENABLE_GLOBAL_SETUP: 'false', ENVIRONMENT: INTEROP }
     secrets-scan:
       runs-on: [az-prod-ubuntu-latest-8Core]
       steps:
         - uses: actions/checkout@<sha>   # fetch-depth: 0
         - uses: gitleaks/gitleaks-action@<sha>
           env: { GITHUB_TOKEN: '${{ secrets.GITHUB_TOKEN }}' }
   ```
   - **No `paths` filter, on purpose.** T2.5 makes `pr-checks / checks` and `pr-checks / secrets-scan` required checks. GitHub leaves a required check pending forever when a path filter skips its workflow, so a PR that only touches, say, the root `README.md` could never be merged. The workflow must run on every PR to `main`, and both jobs must always finish with a result.
   - If the run time becomes a problem, keep the trigger unfiltered and skip expensive **steps** inside the jobs: a first step detects changed paths (`git diff --name-only origin/${{ github.base_ref }}...HEAD`, with `fetch-depth: 0`) and sets an output, and the heavy steps use `if:` on it. Skipped steps still let the job conclude `success`. Never put the condition on the job itself, because a skipped required job blocks the merge in the same way.
   - Use the same `actions/*` versions as the other workflows, pinned by SHA (T2.5 pins the rest).
   - Don't install Playwright browsers; `--list` doesn't need them. If config load still needs secrets (`setup.js` reads `.env`), check which variables `--list` requires and pass dummy values, never real secrets.
   - If gitleaks needs a license for organisation repos, use the gitleaks CLI binary in a run step instead of the action.
3. Write a step summary: each check's outcome in one table (`$GITHUB_STEP_SUMMARY`).
4. **Prove it blocks:** open a throwaway draft PR from a branch off this one that adds each negative case from T2.2 and T2.3 plus a stale catalog. Confirm each step fails, then close the draft PR and delete its branch.
