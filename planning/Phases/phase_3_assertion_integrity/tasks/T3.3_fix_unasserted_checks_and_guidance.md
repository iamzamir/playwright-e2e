## 1. Problem

A static pass on `main` found 43 checks in 28 specs that never do, so those checks cannot fail their test. Nothing in the spec instructions describes the pattern, and nothing catches a new gap at PR time.

## 3. Scope
- **In:** the call sites above; the "Assertions" guidance; a report-only static check for unasserted calls.
- **Out:** rewriting working specs to `expect.soft` (not needed: T3.1 names failed checks); `valuesMatch` migration in page objects (T3.1).

## 4. Implementation steps
1. **Fix each call site** the way the house pattern does it, keeping test intent. Read how the test uses the result first:
   - It only decides what the test does next (an `if`, a setup step): change it to `valuesMatch`.
   - The check matters: keep the boolean and add it to the test's final assertion (or add the final assertion if the test has none, as in PowerBar `Test_002` Test Case 4).
   - It is a step log, not a check (for example "popup closed" inside a recovery path that a later check covers): change it to `logMessage('INFO', …)` and say why in the PR.
   - DataSetup cleanup steps whose failure should not fail the run: change them to `logMessage` with the status, so they stop looking like checks.
2. **Guidance.** Add an "Assertions" section to `.github/instructions/playwright-specs.instructions.md`:
   - Use `commonFunctions.compareTwoValues(actual, expected, '<what is checked>')` for each value check, keep each result in a named boolean (or a `validations` array), and end the test with one hard assertion over all of them: `expect(a && b && c).toBeTruthy()` or `expect(validations.every(Boolean)).toBeTruthy()`. One run then reports every check, and the test still fails if any one failed.
   - Every captured boolean must reach that final assertion. A comparison that is not a check (a probe or a condition) uses `valuesMatch`, never `compareTwoValues`.
   - UI state waits stay web-first: `await expect(locator).toBeVisible()` / `toHaveText()`, not `compareTwoValues(await locator.isVisible(), true, …)`.
   - Messages describe the check ("Scenario name in header"), not the value.
   Mirror it in `.github/agents/playwright-test-author.agent.md` and `playwright-healer.agent.md` only if their examples show a different style.
3. **Static check (report-only).** Add `scripts/check-assertions.js` (`npm run check:assertions`): for each spec, list `compareTwoValues` calls whose result is discarded with no later `expect` on the value, and captured booleans that never reach an `expect` (bracket-match multi-line `expect(...)`, follow `x = a && b` re-assignments, accept `validations` arrays checked with `every`). Exit 0 and print the list; add it to `pr-checks` as an informational step. Once the list is empty, make it fail on new entries (a baseline file, as with the lint baseline).
