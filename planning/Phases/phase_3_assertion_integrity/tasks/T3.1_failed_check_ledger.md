## 1. Problem
`compareTwoValues` is a soft check on purpose: specs keep each result in a boolean and make one hard assertion at the end, so a run reports every check and still fails if any failed (see the phase README). Two things are missing:
1. When that final `expect(a && b && c).toBeTruthy()` fails, the error says "Received: false" and nothing about which check failed. Only the Allure FAIL step names it.
2. A check whose boolean never reaches the final assertion (43 known in 28 specs, plus any new ones) logs FAIL inside a passing test, and nobody sees it.

The fix must not change the pattern: no throw and no `expect.soft` inside the helper (that would report every mismatch twice, and fail tests on the 81 page-object and util calls that use the helper as a probe).

## 2. Evidence (verified 2026-10-16 on `main` @ `865f9848d`)
- `playwright-e2e/util/common.util.ts` `compareTwoValues(sActualValue, sExpectedValue, sLogMessage, bIgnoreCase = false)`: computes `isMatch` (case-insensitive when `bIgnoreCase`; string fallback `String(a) === String(b)`), logs `PASS … Success !! Actual and Expected Values are:: <a>` or `FAIL … Failed!! Expected Value:: <e> || Actual Value:: <a>`, returns the boolean.
- `CommonFunctions` comes from the `commonFunctions` fixture (`configs/fixtures.ts`) and from `new CommonFunctions()` in 58 spec files and in page objects, so per-instance state would miss calls. The ledger has to be module-level, keyed by the running test.
- Probes in page objects and utils: 81 calls (`util/mapping.util.ts` 38, `util/alm-migration.util.ts` 11, `pageobjects/drillthrough.page.ts` 6, …). `pageobjects/planning/views-drawer.component.ts` `allGroupsHaveState` returns `false` on the first mismatch as a normal answer.
- No spec asserts a `compareTwoValues` result as `false`; negative checks pass `false` as the expected value (48 calls).
- Auto fixtures already exist (`_networkCapture`, `_apiCalls` in `configs/fixtures.ts`); `configs/api-fixtures.ts` serves the API specs.

**Corrected 2026-11-06 (`main` @ `ca3c2e1b0`):** page objects and utils now have 84 calls (`alm-migration.util.ts` 12), and 60 specs use `new CommonFunctions()`. Tracing each enclosing method to its callers found **no true probes**: `mapping.util.ts` and `alm-migration.util.ts` return results that specs assert, `allGroupsHaveState` is only ever asserted true (`ViewsBatch/Test_009`), `Test_002_MapViewsToContext:86` reaches an `expect` through `failures`, and no caller expects `false` from a method that uses the helper. The bullets above that call these probes are superseded. No `compareTwoValues` call sits inside `expect.poll`, `toPass` or a retry loop in a way that logs a mismatch first.

## 3. Scope
- **In:** the ledger in `compareTwoValues`, a non-recording `valuesMatch` helper, moving page-object/util probes to it, the auto fixture in both fixture files, the `PW_UNASSERTED_CHECKS` switch, a framework self-test, docs.
- **Out:** switching the guard to `fail` in CI (T3.2); fixing spec call sites (T3.3).

## 4. Implementation steps
1. **Ledger.** In `util/common.util.ts`, keep a module-level `Map<string, FailedCheck[]>` keyed by `test.info().testId` (import `test` from `@playwright/test` only, not from `configs/fixtures`, to avoid a circular import). On a mismatch, after the existing FAIL log, push `{ message: sLogMessage, expected, actual }` when a test is running. `test.info()` throws outside a test (global setup, plain scripts): catch it and record nothing. Check what `test.info()` returns inside `beforeAll`/`afterAll`; record hook mismatches against the hook's info if it has one, otherwise skip them, and note the result in the progress log.
   - Signature, return value and both log lines stay exactly as today (triage reads `Expected Value:: … || Actual Value:: …`).
2. **Probe helper.** Add `valuesMatch(actual, expected, label, ignoreCase = false): Promise<boolean>` with the same comparison and an `INFO` log, never recording. Move the page-object and util calls whose `false` is a normal answer to it (start with `views-drawer.component.ts`, `mapping.util.ts`, `alm-migration.util.ts`; review the rest one by one). Spec calls used only as a condition (`if (!(await compareTwoValues(…)))`, about 7) move too. A page-object call that is a real check the test relies on stays on `compareTwoValues`.
3. **Auto fixture `_checkLedger`** in `configs/fixtures.ts` and `configs/api-fixtures.ts` (flag both for impact review; every spec uses them). After `use()`:
   - Read and clear the test's ledger.
   - Test failed or timed out, ledger not empty: add an annotation `failed-checks` listing the messages (expected and actual), and an Allure step with the same text, so the report names the failed checks next to "Received: false".
   - Test passed, ledger not empty (an unasserted check), by `PW_UNASSERTED_CHECKS`:
     - `off`: nothing.
     - `warn` (default): annotation `unasserted-check` with the messages, and a WARN log line.
     - `fail`: throw `Unasserted check failed: <message> (expected <e>, actual <a>)`, one line per check. An error in fixture teardown fails the test.
   - Clear the ledger on every path, so a retry starts empty.
4. **Self-test** `tests/_framework/compare-two-values.spec.ts` (no browser or environment; excluded from suites and listed in `_unscheduled.json` as a framework self-test): match; mismatch asserted at the end (fails, with `failed-checks` naming it; use `test.fail()`); mismatch never asserted with `warn` (passes, annotation present) and with `fail` (fails); `valuesMatch` mismatch (no annotation); `bIgnoreCase`; null vs undefined; number vs `"1"`; a call outside a test does not throw.
5. **Docs.** `playwright-e2e/README.md` env-var table: `PW_UNASSERTED_CHECKS` (`off` | `warn` | `fail`, default `warn` until T3.2 ends).

## 8. Risks and rollback
- Fixture teardown errors in `fail` mode could hide the original error → `fail` only throws for a test that otherwise passed.
- A page-object probe left on `compareTwoValues` shows up as an unasserted check in `warn` → move it to `valuesMatch` (T3.2 finds them).
- Rollback: `PW_UNASSERTED_CHECKS=off`, or revert.
