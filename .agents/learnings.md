# Shared learnings

This file holds verified, non-obvious facts that AI agents and developers have learned while working in this repo. Each entry is one line, grouped by topic. `AGENTS.md` explains how to use and maintain it. Where the source code and this file disagree, the source code wins, so fix the entry.

## Environment and setup
- The sibling service and UI repos are checked out at `C:\Backend\<repo>`. Workspace search tools can't see them, so use `Select-String` in a terminal.
- Environments and endpoints live in `playwright-e2e/configs/env/` (`environments.ts` one row per environment, `endpoints.ts` one row per endpoint with per-environment `overrides`); `configs/setup.js` applies `buildConfig()` to `process.env` and prints the `[setup] ...` lines. Read those first when debugging a wrong URL. Utils use `getConfig()` / `endpoint()`, a live view of `process.env` (so `applyRealmKeyOverride()` and per-test host swaps show through); specs and POMs still read the legacy `process.env` keys.
- After changing `configs/env` or `setup.js`, run `npm run env:parity` (~2 min: 120 `ENVIRONMENT` × `URL_MODE` × `GATEWAY_TYPE` × input-variant runs of `setup.js` from `origin/main` and the working tree, each in an empty cwd so `.env` can't leak in; report in `reports/env-parity/diff.md`) and `npm run test:config`. Add a rule to `DELIBERATE` in `scripts/env-parity.js` for any intended difference.
- Known backend smoke failures on 2026-10-19, unrelated to config (same with older code): ActionItem `Test_003` TC5 (PUT null status → 500, expected 400) on INTEROP and STAGE; on STAGE also AI `Test_004`/`Test_006` (tenant-configured search/editor/filter content), `ProcessBatch/Test_005` TC7 (process model POST 400) and UI Fields `Test_001` TC17. To tell a config regression from an environment one, rerun the failing files after `git checkout origin/main -- configs/setup.js util/` and diff the failure lists, then `git checkout HEAD -- configs/setup.js util/`.
- Node 23+ strips TypeScript natively but won't resolve an extensionless `require('./env')` to `env/index.ts`; Playwright and ts-node do. `setup.js` falls back to registering ts-node only for plain node (the parity script).
- Gateway path prefixes:

ALM paths (`alm/core|exchange/<seg>`) use a separate segment: `staging` for QA and INTEROP, `psr`, `demo`.

  - Link Management: `links` or `lm`.

## Playwright framework
- In `PlanningListingPage.launchContext`, launching a Process context targets `/process/<name>/processplan/link/1` rather than a view URL; `waitForURL` must accept both `viewId` and `processplan` with `waitUntil: 'domcontentloaded'` or it hangs on client-side SPA routing.
- Entity name generation (`util/unique-name.util.ts`, T4.1): `uniqueName(prefix, maxLength=60)` generates deterministic collision-proof names tagged `_pwauto_<runId>_s<shard>w<worker>_<timestamp><seq>` (base36 timestamp + seq counter). Parses with `parseUniqueName(name)` to extract `runId` and `createdAt`. `configs/playwright.config.ts` sets `PW_LOCAL_RUN_ID` so local workers share the run ID.
- Backend DTO entity name limits: Process Orchestration calendar name maximum length is 100 characters (`CalendarRequestDto`), scenario names default to 60 characters. Process and subprocess creation (`POST /process/template`, `POST /process/{processName}/subprocess`) strictly validates `displayName` against `^[a-zA-Z0-9\s]*$` and `name` against `^[a-zA-Z0-9]*$` (`IBP_40_1003`); names from `uniqueName` contain `_` and must be stripped of `_` or use an alphanumeric-only variant before being passed as `displayName` or `name`.
- Git Bash mangles backslash escapes (`\u001b`, `\[`) and `$` inside inline `node -e '…'` / `sed` edits, and in JS `String.replace` a replacement containing `$` + backtick inserts the text before the match. For edits with escapes or `$`, write a small `.js` file in the scratchpad that uses slice/indexOf (or a replacer function), or use the editor tool.
- Timeouts come only from `getTimeout(tier)` in `playwright-e2e/constants/timeouts.ts`. `PW_TIMEOUT_MULTIPLIER` scales every tier.
- `createdEntities` (T4.2): worker-scoped fixture in both `configs/fixtures.ts` and `configs/api-fixtures.ts`; teardown runs after a worker's last test even when a test failed (the worker restarts) and writes `reports/cleanup/worker-<n>.json`. Entities record the `REALM_KEY` active at `register()`, and the deleters re-apply it, because the per-test `_realmKeyOverride` is already restored at worker teardown. Per-kind registration needs are in `util/entity-deleters.util.ts`.
- Playwright tears worker fixtures down at normal worker shutdown with no current test, so `test.step()`/`test.info()` (and the Allure step calls in `CommonFunctions.logMessage`) throw there. `logMessage` now skips Allure outside a test; a failing test hides the problem, because that worker is torn down under the failed test's info.
- Running a `tests/_framework` spec locally: a local `.env` with `USE_SPECIFIC_TESTS=true` makes the config ignore the CLI path ("No tests found"); prefix the run with `USE_SPECIFIC_TESTS=false PW_ENABLE_GLOBAL_SETUP=false`.
- Registering UI-created scenarios (T4.3): scenarios are user-owned, so specs start `scenarioPage.trackApiRequests(SCENARIO_SEARCH_URL_PART)` in `beforeAll` and call `registerScenario(createdEntities, name, processName, tracker())` (`util/scenario-cleanup.util.ts`) before the create call, so a failure after submit still cleans up. That passes the user's token and the context's own search body (`sourceIds`) to the deleter, and `afterAll` calls `createdEntities.cleanupFile()` before the user token can expire. On INTEROP Azure (2026-11-02) the search with the scoped machine token (`'Bearer ' + getBearerToken()`) also returns 200; the deleters' unscoped `buildAuthHeaders()` is untested there for scenarios. A scenario the search doesn't find is logged as "Deleted".
- Registering UI-created scope filters (T4.3): the `scopeFilter` deleter requires an entity `id` (`DELETE .../presets/{id}`), which the UI creation flow does not expose; specs retrieve the saved id via `listSavedFilters(filterAccess)` with `expect.poll` immediately after save and register with `createdEntities.register('scopeFilter', filterName, { id, authorization, context })`.
- Local PS runs: with a local `.env` set up for Gravitee, PS INTEROP specs fail on the missing `GRAVITEE` test-data block; prefix `GATEWAY_TYPE=AZURE` (worked for ScenarioBatch, 2026-11-02).
- `playwright-po-backend-suite.yaml` runs its batches in parallel in one checkout with distinct `PW_REPORT_TAG`s, and every batch's worker indices start at 0. A per-worker artifact path needs the tag in its name, as `buildVideoDir` and the `createdEntities` cleanup report do.
- Raw ms to tier when migrating old code: `5000` SHORT, `10000` MEDIUM, `15000` LONG, `30000` XLARGE, `60000` EXTREME.
- `apiUtil.processAPIRequest(..., 'status')` returns the bare status only for 2xx; a non-2xx comes back as an object (`{ status: '404', ... }`), so `isStatus(result, 404)` never matches. Use `'full'` and check `response?.status` when non-2xx codes are acceptable.
- `catch (error)` is typed `unknown`; read the message with `error instanceof Error ? error.message : String(error)`.
- Bulk regex edits of imports tend to create duplicate-identifier errors. Edit imports with exact-context replacements, then check for TypeScript errors.
- In planning-mfe and lui source, `dataTestId`, `props` and `testId` are variable names, not DOM attributes. Confirm the real rendered attribute before using it as a locator. Unique test IDs (case-insensitive scan of `origin/main` `*.ts,*.tsx`, the `ui-inventory.md` method): planning-mfe 1,083, lui 910 (2026-10-05).
- ABP-19158 (2026-09-16) retired the old Scenario/View UI in both frontends: `WITH_NEW_SCENARIO_FILTER` and `WITH_NEW_VIEW_FILTER_UI` no longer exist (automation still toggles them in `UIDataReset/Test_004` — no-ops), and lui lost `drawer-close-btn`, `pinned-icon`, `unpinned-icon` (still in planning-mfe, where the POMs use them).
- planning-mfe dirty state is on by default since ABP-19438 (2026-09-29); `WITH_DIRTY_STATE` now only turns it off.
- A non-empty unknown `SUITENAME` (no matching `tests/TestSuites/<name>.json`) throws at config load, listing available suites; a suite with empty `testFiles` also throws. An unset or whitespace-only `SUITENAME` runs by CLI path or filters without throwing. `setup.js` has no `SUITENAME` default, and `USE_SPECIFIC_TESTS=true` reads `SPECIFIC_TESTS` or gitignored `configs/specific-tests.local.json` (verified 2026-10-08).
- `commonFunctions.compareTwoValues()` logs PASS/FAIL and returns a boolean; it never throws, so its result must reach `expect()`. Each mismatch also goes in a per-test ledger: the `_checkLedger` auto fixture adds a `failed-checks` annotation to a failing test, and handles a passing test with a mismatch by `PW_UNASSERTED_CHECKS` (`warn` default: `unasserted-check` annotation and WARNING step; `fail`; `off`). Use `valuesMatch()` for a probe whose `false` is a normal answer.
- `beforeAll` and `afterAll` run outside test-scoped fixtures, and test fixtures never start when `beforeAll` fails (Playwright 1.62, observed). So the ledger annotates those mismatches at once as `hook-failed-check`; `PW_UNASSERTED_CHECKS=fail` cannot enforce them. A `beforeAll` annotation is copied to every test in its scope, and an `afterAll` one lands on the last test, so count `hook-failed-check` per check, not per test. Record before any `await`: after one, `test.info()` can already be a different test.
- A fixture that can fail a test from teardown must be the last auto fixture, so it tears down first: `_apiCalls`, `_failureCapture`, `_networkCapture` and `_observability` choose their evidence from `testInfo.status`, and a teardown throw updates that status at once for the fixtures after it (observed on Playwright 1.62).
- `generate-testcase-docs.js` joins every `describe` title in a file with ` › ` and lists all its tests under that one suite, so sibling `describe` blocks read as nesting in the catalog. Prefer one `describe` per spec.
- To count failed checks on passing tests, match `[FAIL]` steps containing `Expected Value::`. Counting every failed step overcounts badly: API tests that expect an error also log `[FAIL]`, and those never reach the ledger.
- Before adding a captured `compareTwoValues` boolean to a final assertion, check how the test uses it: `ScopeBatch/Test_007` uses one to decide whether to apply a filter, so asserting it would fail the test. Such a probe belongs on `valuesMatch`.
- ALM validation (`Migration/Test_007`) can run well past the spec's 10 × 3 s poll: its status was still `IN_PROGRESS` when polling ended, and one attempt reached `FAILED` after about 80 s (observed 2026-11-04 and 05). `IN_PROGRESS` at the end of that poll is slowness, not a stuck service.
- Triage takes the last failed Allure step as `failedStep`, so a summary step added after the real check must not be logged as FAIL.
- There is no `LOG_LEVEL` switch in the framework (checked 2026-10-05, all branches): `CommonFunctions.logMessage(level, msg)` always writes winston (`PASS`/`INFO` → info, `WARNING` → warn, `FAIL` → error, plus `logs/` error file) and an Allure step. `FAIL` and `ERROR` lines are written with `allure.logStep(name, Status.FAILED)`, so they appear as failed steps without failing the test.
- After portal sign-out, entering a realm and clicking Continue opens a B2C popup that starts as `about:blank`, then shows "Blue Yonder User Store (SSO)" and a Support Sign In *link* (not a Continue button). Wait for the popup to leave `about:blank` before clicking SSO. `btnSupportSignIn` must match `link` as well as `button`.
- Visual runs (`playwright.visual.config.ts`): baselines resolve to `testdata/<ENV>/VisualBaseValidations/{testFileDir}/<name>.png`, with `{testFileDir}` relative to `tests/VisualAutomation/VisualSpecs`, so a spec moved between area folders needs its baseline moved too. A missing baseline fails in CI (`ensureBaselineExists`), so never add a spec to a `VisualSuites/*.json` suite without committing its baseline.
- Visual noise outside the app (T9.11, 2026-11-12): the portal header icons (`[data-testid="lui-portal-appbar-icons-container"]`: realm tag, AI assistant, collaboration, `99+` notification badge) change with portal releases and per-user counts, and `#portal-bg` (`data-testid="luminate-portal-background"`) paints an animated canvas behind the header and page frame, so two captures never matched in strict mode. `validatePage/validateArea({ stableCapture: true })` masks the icons and applies `constants/visual-stable-capture.css` (canvas hidden, solid navy, no scrollbars). `toHaveScreenshot` accepts only `stylePath`; a `style` string is silently ignored, while `page.screenshot` takes `style`.
- `VISUAL_FORCE_DIFF` marker (since #692) was appended in flow to `<body>`, below the 100vh portal, so it never showed in a full-page capture; it is now `position: fixed` in the content area. Even visible (~1,000 px) it passes the default 2% tolerance (~41,000 px at 1920x1080), so a mocked spec with `stableCapture` uses `maxDiffPixelRatio: 0` (3 of 3 local replays matched pixel for pixel).

## Process Orchestration (PO) service
- Start/Close Process is asynchronous: `TransitionHelper.startNode`/`stopNode`/`postTransitionRequests` are `@Async("asyncTaskExecutor")` and walk the hierarchy node by node (running linked procedures), so child statuses land after the parent's. The node the user closes becomes `COMPLETED` (level 1) and its descendants `AUTO_COMPLETED`. UI checks must refresh-and-poll (`ProcessPage.refreshAndVerifyStatus`/`waitForStatus`/`verifyGrandchildStatusText`), not sleep.
- Both UIs' `useApi` prepends the PO base URL to any URL that doesn't contain `http` (mfe `config.apiURL`, lui `config.apis.poAPIUrl`).
- Check PO DTO and response shapes in the controller and service source. Earlier exploration subagents invented these shapes.
- `PUT /process/{p}/scope`: the body replaces the whole scope with no validation, and every call writes an audit row. Always send back exactly what `GET` returned.
- `GET /process/{p}/scope`: `dimensions` and `horizon` are optional. PSR `IntegratedBusinessPlanning` returns neither, and lui reads `scope?.dimensions`. Assert that the body is a JSON object, not that it has keys (PSR smoke run, 2026-09-24).
- `POST /process/{p}/validate/SCENARIO`: defaults to `isAsync=true`, which writes a job row. Send `isAsync=false` for a synchronous check. The sync call fans out to the simulation and assumptions services.
- Calendars: creating or updating a cycle on a calendar a process uses writes `node_schedule` rows. Deleting a calendar in use returns 409 (2006). A duplicate calendar name returns 409 (2020). A cycle whose start date matches another cycle in the same calendar returns 400 `IBP_PO_40_2100` "Calendar cycle name … already exists" (`CalendarService.createCycle` checks start date and name), so the message names the cycle even when only the date clashed. Shared static calendars (e.g. `'Monthly Calendar'`) pre-exist in target tenants and cannot be deleted, causing `assertAbsent` in ALM migration `Test_009` TC9 to fail persistently.
- Supply chain actions:
  - `(tenant_id, name)` is unique, and `name`, `procedure_name` and `ui_config` are NOT NULL.
  - `PUT` replaces the whole entity, so send every required field.
  - These routes have no RBAC check.
  - planning-mfe runs `JSON.parse(uiConfig)`, so use `"{}"` rather than an empty string.
- PO export error payloads replace entity arrays (`processes`, `calendars`, etc.) with `{ isDataExportSuccessful: boolean, errorReason: string }` objects; always guard entity extractors with `Array.isArray()`.
- ALM migration `Test_009` TC8 must set `cleanupCompleted` from the non-empty, all-success deletion results, not merely from `runCleanup()` returning; otherwise a failed cleanup assertion skips TC9 and the `afterAll` retry. Verified false, empty, thrown, successful, and repeatedly failing cleanup paths with isolated spec callbacks (2026-11-06).
- Machine subject unassignment from IAM roles (`DELETE /iam/realm/v1/roles/{r}/subjects/{s}`) can return 403 Forbidden under strict realm security policies (e.g. `cbpf-test23`), causing subsequent role deletion to return 409 Conflict.
- PO serves `GET /tenant` and `GET /supplyChainAction` from v2 controllers (`TenantControllerV2`, `SupplyChainActionControllerV2`), which a `*Controller.java` filename filter misses. Grep `@GetMapping` across all files.
- `POST /process/search` ignores `sort` and always orders by `created_on DESC`; sending any `sort` element returns 500 (PO-D04).
- `POST /process/search` (verified 2026-10-01, INTEROP/QA both gateways): rows return the display status (`Not Started`) for a raw filter (`NOT_STARTED`); null columns come back as the string `"null"`; custom attributes without UI Fields value names are dropped from row `attributes`; `totalPages` is one too high on exact multiples. Known defects PO-D01 to PO-D10 are in `docs/Coverage/PSR-Gap-Plans/ActionItems-UIFields-Defect-Report.html`.
- RBAC-guarded PO routes (`/context`, `/scope`, `/processGantt`, GET subprocess) answer an unknown or wrong-case process name with `401 IBP_40_1032`, not 404. Unguarded ones differ: `/entity/{type}` gives `404 IBP_PO_40_2002`, `/users` gives `401 IBP_40_1005`, KPI routes and `/subprocess/{sp}/children` give `200` empty.
- `GET /process/{p}/context` drops custom attributes that `GET /process/{p}` returns (PO-D07), and a non-numeric `scope.horizon.pastDays`/`futureDays` makes every context call return 400 (PO-D08), so never store one outside a dedicated process.
- `util/process-fixture.util.ts` creates a process from a template and deletes it with its model, procedure, actor and IAM roles; use it for any spec that needs a writable process.
- Process and child/subprocess display names allow only letters, digits and spaces (`400 IBP_40_1003`, NodeService.java); `uniqueName()` output with underscores is rejected by both process and child process creation. Use `uniqueAlphanumericName(prefix)` from `util/unique-name.util.ts`. After `deleteProcessWithReferences`, `GET /process/{p}` returns `401 IBP_40_1032` (absent), the `_admin` role delete returns 409 (machine unassign 403) and the process-model delete 400; the process itself is gone.
- PO Global Settings View Group modal (`ViewGroupsAddEditModal.tsx`) sets container name `maxLength: 50` (`CONTAINER_MAX_LENGTH`). Use `uniqueName(prefix, 50)` so the generated string stays within 50 characters and does not get truncated by the browser input.
- `GET /supplyChainAction` (v2) omits `uiConfig` and audit fields; `GET /supplyChainAction/{id}` includes `uiConfig` but omits it when blank. Duplicate name or missing NOT NULL field → `400 IBP_40_1031`.
- `POST /tenant/onboard` has no current UI caller.
