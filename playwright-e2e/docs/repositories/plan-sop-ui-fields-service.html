UI Fields Service

The configuration-driven rendering service. It tells the Process Orchestration UI (lui) which fields, columns, filters, groups, rules, and UI components to display for a page and tenant. Planning Space does not call it.

What this repository does

The service externalizes UI structure into tenant-scoped metadata: list-page columns, detail-page field groups, editor definitions, filter configuration, attributes and values, and a UI component registry. lui calls four of its routes (list-page-config, list-page-config-with-filter, detail-page-config, page/{name}/editor) through config keys in src/config.ts to render the PO listing, process/subprocess/calendar details, and every create/edit form.

A configuration change can remove a field while every API still returns 200; the visible symptom is a lui locator failure that looks like a frontend defect. Since 2026-10-01 two backend specs diff those four routes against per-environment baselines, so the drift fails at the API layer first.

Functional capabilities

Page configuration

  • Return list-page columns and combined list/filter metadata.
  • Return detail-page field groups and named-page editors.
  • Register pages and resolve a page name to its numeric ID.
  • Return filter-panel configuration.

Attributes and values

  • Create, read, update, and delete attributes by entity type and name.
  • Manage allowed attribute values.
  • Resolve value names in bulk.
  • List all tenant attributes.

UI fields and rules

  • CRUD fields by ID and list all tenant fields.
  • Group fields into page sections.
  • Associate a field with a registered UI component.
  • Apply conditional visibility and requirement rules.

Subscriptions and migration

  • Subscribe an entity attribute to a named page.
  • Update and remove subscriptions.
  • Import and export tenant metadata.
  • Expose POST /echo for diagnostics.

Triage order: page registered → field present in list/editor config → attribute exists → field rule permits visibility → UI component unchanged. Only then investigate frontend code.
