What this repository does

The active playwright-e2e/ framework tests two React micro-frontends and the supporting backend services. It combines browser journeys, direct API contracts, destructive data setup, source/target-realm migration, visual snapshots, and navigation performance. The top-level e2e/ is the legacy WebdriverIO suite; jmeter/ holds load and performance plans.

Environment selection, URL routing, credentials, realm identity, gateway mode, and every endpoint prefix are centralized in configs/setup.js. Specs consume injected fixtures, page objects own locators, utilities own API/domain operations, and test-data JSON owns environment-specific values.

Framework capabilities

UI and API testing

  • Fixture-injected page objects for Planning Space and LUI.
  • Axios-based API client with OAuth token caching and redaction.
  • DB verification through MSSQL utilities.
  • Domain helpers for process start, mapping, calendars, and ALM migration.
  • API-spec helpers: ActionItemApiHelper (single-send writes), process-fixture.util.ts (writable processes with full cleanup), ui-fields.util.ts (baseline diffs), processRawRequest for malformed JSON.

Environment and identity

  • QA, INTEROP, and PSR data and routing.
  • OLD and NEW path modes.
  • AZURE and GRAVITEE gateway modes.
  • User1/user2 and source/target realm credentials from environment variables.

Evidence and observability

  • Allure, Monocart, and Playwright HTML reports.
  • Traces, video, screenshots, and controlled network artifacts.
  • Visual diff helpers and environment-specific baselines.
  • Winston logs and Teams visual reporting.

Execution and maintenance

  • Suite JSON selection and targeted test scripts.
  • Parallel backend-batch runner.
  • Environment-aware codegen and spec finalization.
  • Generated test-case documentation, a generated backend API coverage dashboard (npm run docs:api-coverage), and Allure trace stripping.
  • Shared agent learnings and skills in .agents/.

Principal gaps

  • No accessibility baseline across 155 functional UI specs.
  • 23 endpoints used by the UIs still have no backend test (mostly PO transitions, Action Item bulk, subprocess start/stop).
  • UI Fields coverage stops at the four page-config routes lui calls.
  • PSR and QA test-data coverage is much thinner than INTEROP.
  • Visual coverage is small relative to functional coverage.
  • Action Item playbooks and LUI settings remain untested.
  • No CI guard keeps all services on the same Commons SHA (they currently match).

Authoring and governance

Definition of Done

  • Fixture injection and serial grouping where ordered.
  • Locators in page objects only; no XPath.
  • Deterministic waits through getTimeout(tier).
  • Matching test data for each target environment.
  • Suite JSON registration and regenerated test-case docs.
  • No TypeScript errors and isolated run with one worker.

Safety constraints

  • Do not commit directly to main or shared integration branches.
  • Never hardcode credentials or bearer tokens.
  • Never interleave destructive data setup with functional suites.
  • Do not bypass hooks or skip tests merely to make CI green.
  • Do not change a widely called POM signature; add and deprecate.
Timeout model: tiers range from TINY 2s to EXTENDED 30 minutes. PW_TIMEOUT_MULTIPLIER scales them for slow environments; hardcoded waitForTimeout calls are prohibited.
