Action Item Service

What this repository does

The service is the system of record for work that must be completed by a user or team. An action item is attached to a source entity such as a process, subprocess, or assumption. It carries assignee, status, dates, comments, custom attributes, KPI mappings, notifications, and audit information.

It also owns playbooks: reusable definitions containing action-item templates. Initiating a playbook creates a separate instance and instance items. Editing the definition later does not mutate running instances.

Functional capabilities

Action-item lifecycle

  • Create one item or create in bulk.
  • Read by item ID or source entity.
  • Edit details, extend a due date, and update status in bulk.
  • Delete one, delete a supplied set, or delete every item for an entity.
  • Search with server-side criteria via POST /searchActionItems.

Playbooks

  • Define a named playbook and its item templates.
  • Initiate manual or recurring instances.
  • Update individual or bulk instance-item statuses.
  • Read grouped instances and history; archive completed definitions.
  • Recurring initiation is cluster-guarded by ShedLock.

Collaboration and notifications

  • Create collaboration channels through a proxy.
  • Store comments and remove all comments for an entity.
  • Map source events to recipients and delivered user notifications.
  • Resolve users and entity users through RBAC proxies.

KPI and metadata

  • Create KPIs, configure attributes, and map KPIs to entities.
  • Serve editor, summary, and filter field configurations.
  • Manage pages, UI components, custom attributes, allowed values, field groups, and conditional rules.
  • Import and export tenant configuration.

Automation decision: use the PO proxy when testing process-level authorization. The direct route bypasses that layer and is best for fast setup, cleanup, and service-native CRUD.
