PO Backend Commons

The non-deployable library compiled into every PO backend service. It standardizes security, gateway integration, HTTP clients, auditing, Kafka events, logging, APM, persistence plumbing, operations support, and Key Vault access.

What this repository does

The library removes cross-cutting duplication from Process Orchestration backend services. A consumer adds the artifact and receives common JWT and RBAC behavior, Gravitee and WebClient support, structured logging, Elastic APM, Kafka audit publishing, Liquibase/JPA/MapStruct plumbing, Azure Key Vault integration, and shared operational database-state support.

It has almost no HTTP API of its own. Its importance is its blast radius: one version change can alter authentication, serialization, logging, migrations, or auditing in all four services simultaneously.

Capabilities contributed to consumers

Security and gateway

  • JWT validation through Nimbus JOSE JWT.
  • Shared @ibp.hasAction(...) RBAC expression root.
  • Uniform 401 and 403 response behavior.
  • Gravitee request and operational integration.
  • Central operations-admin identities via PO_OPS_ADMINS.

HTTP and observability

  • Shared WebClient configuration with a 30 MB codec limit.
  • ECS structured Log4j2 layout.
  • Elastic APM instrumentation and cross-service trace IDs.
  • HTTP filters and MDC context.

Data and platform

  • JPA, Liquibase core, and MapStruct dependencies.
  • Auditable fields such as createdBy and updatedBy.
  • Azure Key Vault resource lookup.
  • Operations database-state endpoints and checks.

Audit eventing

  • Kafka po-audit-log-producer.
  • Realm allowlist before publishing.
  • Asynchronous, fire-and-forget delivery.
  • Configurable topic, brokers, and acknowledgement pool.

    A--)K: fire-and-forget publish
    K--)E: persist
  else realm disabled
    A->>A: drop event
  end
Operational consequence: Kafka failure does not fail the business API. A green functional suite does not prove audit delivery is healthy.

Automation strategy

Direct E2E tests against port 9999 or GET /hello would test a sample host rather than the behavior consumers ship. Commons is correctly tested through its own unit/Testcontainers tests and indirectly through every backend contract spec.

CapabilityObservable automation signal
JWT / RBACUniform 401/403 across all services
Auditable identitycreatedBy/updatedBy match the expected user subject
Codec limitLarge payload boundaries across mapping and migration endpoints
APM / logsTrace IDs and the same ECS schema across services
Audit producerPoll the downstream audit store after a mutation
Recommended guard: CI should compare the pinned Commons SHA across all four consumers and fail when they differ.
