What this repository does

This service owns the domain objects that organize planning work. A process is the root of a hierarchy; subprocesses are child nodes. Nodes can carry attributes, schedules, transitions, event actions, reports, scope, and action items. Calendars and cycles determine execution dates, while start/stop and transition events advance runtime state asynchronously.

It is also the platform's configuration migration hub. It exports and imports process data, publishes exchange packages to ALM, deploys configuration into another realm, and exposes job-status endpoints for long-running operations.

Functional capabilities

Process hierarchy and lifecycle

  • Create from scratch, template, or import.
  • Read process, children, full tree, context, scope, status, users, and Gantt data.
  • Create, edit, start, stop, and delete subprocesses.
  • Start and stop asynchronously; validate entity limits and update plan dates.

Calendar, schedule, and transitions

  • CRUD calendars and nested cycles.
  • Attach node schedules to calendar cycles and reschedule processes.
  • Create process or subprocess transitions and generate transition trees.
  • Poll transition jobs separately from generic jobs.

Configuration and governance

  • Manage templates, template schemas, exclusions, and template entities.
  • Define quotas, metering rules, and enforcement scopes.
  • Configure reporting workspaces, folders, insights, subscriptions, and event actions.
  • Onboard tenants, users, roles, machine credentials, and LIAM resources.

Integration and migration

  • Proxy process-scoped action-item calls to Action Item.
  • Proxy users, resources, permissions, and procedure onboarding.
  • Export/import tenant data and publish/deploy ALM configuration.
  • Emit and consume Kafka events, webhooks, notifications, and mail.

ALM migration

sequenceDiagram
  participant T as Migration test
  participant S as Source realm
  participant A as ALM Exchange
  participant D as Destination realm
  T->>S: export process or POST /exportData
  S-->>T: package
  T->>S: POST /configuration/exchange/publish (ZIP <= 10 MB)
  S-->>T: jobId
  T->>S: poll /job/{jobId}/status
  T->>A: deploy resource
  A->>D: apply configuration
  T->>D: poll status, then GET process
Important: a 2xx response from the start, stop, transition, import, export, or exchange endpoint does not prove completion. Automation must poll the matching status endpoint.
