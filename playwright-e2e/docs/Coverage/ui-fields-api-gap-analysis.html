Evidence and Review Findings

  • 05-Oct: the Playwright suite has a UIFields/ folder with test data for INTEROP and QA. UI Fields field lists are tenant-configured, so expected lists differ per environment (QA lists processName, adds participants and has 6 status filter keys).
  • 05-Oct: the 28 active operations exclude 3 deprecated subscription routes and 2 @Profile("local") mock routes; the 31-Aug count of 32 came from OpenAPI and included /ops/db/state.
  • The external suite covers Action Item, Calendar, Link Management, Migration, and Process Batch scenarios. Its full-export fixture contains a customFields object, but no scenario invokes /ui-field, /entity/.../attribute, page/configuration, subscription, or operational endpoints.
  • The service Postman collection covers attribute CRUD/value CRUD, UI-field CRUD, pages, three configuration reads, components, and import/export. It has no requests for subscriptions, /echo, /list-page-config-with-filter, or /ops/db/state.
  • Contract drift: OpenAPI lists 200 for all create operations, but the controllers return 201 Created for POST attribute, POST attribute values, POST UI field, and POST subscription. Align the specification before using it as a strict automated assertion source.
  • The sampled external Action Item data includes fixed UUIDs and a 2025 due date. New UI Fields tests should generate unique names and obtain IDs from preceding responses so runs stay repeatable.
